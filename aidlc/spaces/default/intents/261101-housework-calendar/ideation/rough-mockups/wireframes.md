# ラフな画面イメージ（Wireframes）

最初の版の画面と、LINE のトークでの操作を大まかに描いたものです。もとにしたのは次の書類と回答です。

- 「意図の整理」（`ideation/intent-capture/intent-statement.md`）
- 「範囲の定義」（`ideation/scope-definition/scope-document.md`）
- 「作業一覧」（`ideation/scope-definition/intent-backlog.md`）
- `rough-mockups-questions.md` の回答（Q1〜Q8）

見た目より使いやすさを優先した、構成だけのイメージです（Q6）。画面ごとに、作業一覧のどのまとまり（IB-n）に当たるかを書いています。

## 全体の構成（Information Architecture）

アプリの画面（LINE の中で開く画面。母親はパソコンのブラウザでも開く。Q1）は次のとおりです。

- カレンダー（ホーム）: 全員が使う。IB-4
  - 日の詳細: 全員が使う。修正できるのは母親だけ。IB-4、IB-6、IB-3
- お小遣い: 全員が使う。IB-8
  - 加算・減額の入力: 母親だけ。IB-9
- お手伝いの種類: 母親だけ。IB-2
- 月の割り当て: 母親だけ。IB-3

LINE のトークでの操作は次のとおりです。

- 公式アカウントとの 1 対 1 のトーク（子供）: リッチメニューから記録する。IB-5、Q4・Q8
- 家族のグループのトーク
  - 毎日 16 時のリマインド（IB-10）
  - 枠の交換（IB-7、Q5）
  - 月末のまとめ（IB-11）

画面のいちばん下に、画面を切り替えるタブを置きます。

- 母親: 「カレンダー」「お小遣い」「設定」の 3 つ。「設定」の中に「お手伝いの種類」と「月の割り当て」がある
- 子供: 「カレンダー」「お小遣い」の 2 つ

## S1. カレンダー（ホーム）

アプリを開くと最初に表示される画面です（Q2）。

```
[ < 2026年12月 > ]                 (月の切り替え)
------------------------------------------------
| 日 | 月 | 火 | 水 | 木 | 金 | 土 |
|  1: 皿洗い=太郎(済) / 風呂=花子(未)        |
|  2: 皿洗い=花子(済) / 洗濯たたみ=次郎(×)   |
|  ...                                        |
------------------------------------------------
今月のお小遣い(ここまで)
  太郎 1,200円 / 花子 900円 / 次郎 600円
------------------------------------------------
[カレンダー] [お小遣い] [設定(母親のみ)]
```

- 日付ごとに、その日のお手伝いと担当の子供を表示します。状態は「済」「未」「×（やらなかった）」の文字でも表すので、色だけに頼りません（Q7）
- 日付をタップすると S2（日の詳細）を開きます
- 子供も、家族全員の担当とお小遣い額を見られます（`scope-document.md`）
- スマホでは週ごとの縦の一覧、パソコンでは 7 列の月表示にします（Q1）
- 表示の状態
  - 割り当てがない月: 「この月の割り当てはまだありません」と表示する。母親には「割り当てを入力する」ボタンも出す
  - 読み込み中: 枠だけを先に表示する
  - 読み込みに失敗したとき: 「表示できませんでした。もう一度お試しください」と再読み込みのボタンを出す
- 見やすさのメモ: 見出しは「2026年12月」（h1）。画面の領域は header（月の切り替え）、main（カレンダー）、nav（下のタブ）。キーボードでは、最初に月の切り替えにフォーカスが当たる

## S2. 日の詳細

```
12月2日(水)
------------------------------------------------
皿洗い       担当: 花子   済 (16:42 に記録)
             [記録を取り消す](母親のみ)
洗濯たたみ   担当: 次郎   未
             [やらなかったにする](母親のみ)
             [担当を変える](母親のみ)
------------------------------------------------
[戻る]
```

- 記録した時刻を表示します。取り掛かりの様子をあとで確認するためです（`intent-statement.md`）
- 子供が記録した時点で回数に数えます。母親はあとから取り消せます（`scope-document.md`）
- 「やらなかった」は母親が記録します。自動では判定しません（`scope-document.md`）
- 「担当を変える」で、月の割り当てのあとに日ごとの修正をします（Q3）
- 取り消しと「やらなかった」の前には、「この記録を取り消しますか？（皿洗い・花子・12月2日）」のように、何が変わるのかを書いた確認を出します
- 見やすさのメモ: 見出しは日付（h1）。お手伝いごとに h2 を付ける。領域は header と main。キーボードでは、最初のお手伝いの操作ボタンにフォーカスが当たる

## S3. お手伝いの種類（母親のみ）

```
お手伝いの種類                     [+ 追加]
------------------------------------------------
皿洗い       100円   [編集]
風呂掃除     150円   [編集]
------------------------------------------------
(編集)
  名前   [ 皿洗い            ]
  単価   [ 100 ] 円
  説明   [ 食器を洗って水切りかごに並べたら完了 ]
  [保存] [やめる]
```

- 設定できるのは名前・単価・説明（やり方や、できたと言える基準）です（`scope-document.md`）
- 種類がまだないとき: 「お手伝いの種類がありません。最初の種類を追加しましょう」と追加ボタンを表示します
- 入力に誤りがあるとき: 項目のすぐ下に「単価は 0 円以上の整数で入力してください」のように、何をどう直せばよいかを表示します。入力した内容は消しません
- 見やすさのメモ: 見出しは「お手伝いの種類」（h1）。入力欄には必ず見える名前を付ける。キーボードでは、最初に「追加」ボタンにフォーカスが当たる

## S4. 月の割り当て（母親のみ）

```
2027年1月の割り当て
------------------------------------------------
皿洗い     担当 [太郎 v]  日 [x]月 [ ]火 [ ]水 [x]木 [ ]金 [ ]土 [ ]日
           担当 [花子 v]  日 [ ]月 [x]火 [ ]水 [ ]木 [x]金 [ ]土 [ ]日
           [+ 担当を追加]
風呂掃除   担当 [次郎 v]  日 [x]月 ... 
------------------------------------------------
[カレンダーで確認] [保存]
```

- お手伝いの種類ごとに、担当の子供と曜日を選びます。保存すると、その月の日ごとの割り当てができます（Q3）
- 保存したあとは、S2 の「担当を変える」で日ごとに修正できます（Q3）
- 同じ日の同じお手伝いに 2 人の担当が重なったときは、保存前に「1月5日(火)の皿洗いに担当が 2 人います」と知らせます
- 前の月の割り当てをコピーする機能や、自動で割り当てる機能は付けません（`scope-document.md`）
- 見やすさのメモ: 見出しは「2027年1月の割り当て」（h1）。お手伝いごとに h2 を付ける。曜日のチェックボックスには「月曜」のような名前を付ける。キーボードでは、最初の担当の選択にフォーカスが当たる

## S5. お小遣い（全員）

```
2026年12月のお小遣い
------------------------------------------------
太郎   皿洗い 100円 x 8回 = 800円
       風呂掃除 150円 x 4回 = 600円
       加算・減額: -200円 (理由: 部屋の片付けを約束したのにしなかった)
       合計 1,200円
花子   ...
------------------------------------------------
[加算・減額を入力](母親のみ)
```

- 「お手伝いの種類ごとの単価 × 実施回数」の合計を、内訳つきで表示します（`intent-statement.md`）
- 加算・減額は、理由とあわせて表示します（`scope-document.md`）
- 記録がまだない子供: 「今月の記録はまだありません（0 円）」と表示します
- 見やすさのメモ: 見出しは「2026年12月のお小遣い」（h1）。子供ごとに h2 を付ける。金額は数字と「円」の文字で表す

## S6. 加算・減額の入力（母親のみ）

```
加算・減額
------------------------------------------------
子供   [太郎 v]
種類   ( ) 加算  (x) 減額
金額   [ 200 ] 円
理由   [ 部屋の片付けを約束したのにしなかった ]
[保存] [やめる]
```

- 理由は必ず入力します（`scope-document.md`）
- 1 月にも間に合いそうにない場合は、この画面だけを最初の版から外します（`intent-backlog.md` の IB-9）
- 見やすさのメモ: 見出しは「加算・減額」（h1）。加算と減額は、ラジオボタンに文字の名前を付けて選ぶ

## T1. 1 対 1 のトーク: リッチメニューで記録する（子供）

```
(公式アカウントとの1対1のトーク)

          [ 今日の担当: 皿洗い ]  [ 風呂掃除 ]    <- 返事のボタン
  公式: どれをやりましたか？
                                   太郎: やった   <- メニューから
------------------------------------------------
| [ やった ]        | [ カレンダーを開く ]      |  <- リッチメニュー
------------------------------------------------
```

- リッチメニューの「やった」をタップすると、自分の今日の担当がボタンで出てきます（Q4）
- 担当を選ぶと、「皿洗いを記録しました（16:42）」と本人に返事が届きます。グループには知らせません（Q8）
- 今日の担当がないとき: 「今日の担当はありません」と返事します
- すでに記録したお手伝いは、「済」と表示して選べないようにします。同じ記録が二重にできないようにするためです
- 「カレンダーを開く」で S1 を開きます

## T2. グループのトーク: リマインド、枠の交換、月末のまとめ

```
(家族のグループのトーク)

  公式: 今日の担当です (12/2 16:00)
        太郎: なし / 花子: 皿洗い / 次郎: 洗濯たたみ

  花子: 交換
  公式: 交換したい担当を選んでください
        [12/3 皿洗い] [12/5 皿洗い]
  公式: 花子が 12/3 の皿洗いの交換を申し出ています。
        引き受ける人は選んでください
        [太郎: 12/4 風呂掃除と交換] [次郎: 12/6 洗濯たたみと交換]
  公式: 太郎の 12/4 風呂掃除と、花子の 12/3 皿洗いを交換しました

  公式: 12月のお小遣い (12/31)
        太郎 1,200円 / 花子 900円 / 次郎 600円
```

- 毎日 16 時に、その日の担当を 1 回だけ送ります（`scope-document.md`）
- 枠の交換は、グループのトークで申し出ます。公式アカウントの返事のボタンで、相手の子供が承諾します（Q5）
- 承諾ボタンを押せるのは、申し出た子供以外の子供だけです。それ以外の人が押したときは、「この申し出には応えられません」と返事します
- 月末に、各子供のお小遣い額をまとめて送ります（`scope-document.md`）

## Assumptions & Open Questions

- [assumption] リッチメニューは、家族のグループのトークには出ず、公式アカウントとの 1 対 1 のトークにだけ出る前提で描いた。グループに出るとわかった場合も、記録は 1 対 1 のトークで行い、グループには知らせない（Q8）
- [assumption] グループのトークで「交換」と送ると交換を始める形にした。リッチメニューがグループに出ない場合、交換の始め方はこの形になる
- [assumption] 母親がパソコンで使うときは、ブラウザで LINE にログインして開く（Q1）。パソコン版の LINE ではリッチメニューが出ないが、母親はリッチメニューを使わないため影響しない
- [assumption] 子供の名前（太郎・花子・次郎）と金額は、画面イメージのための例
