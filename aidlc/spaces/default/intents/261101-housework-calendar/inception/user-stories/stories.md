# ユーザーストーリー（Stories）

要件（`inception/requirements-analysis/requirements.md`）を、母親（P1）と子供（P2）の目線のストーリーにしたものです。人物は `personas.md` を参照してください。並び順は使う流れの順で（Q2）、1 つのストーリーは要件のまとまり 1 つに対応します（Q3）。受け入れ条件は Given/When/Then で書き、そのまま BDD の筋書きのもとにします（`inception/practices-discovery/team-practices.md`）。

- 優先度: US8.2（加算・減額）だけが Should Have で、ほかは Must Have（`ideation/scope-definition/intent-backlog.md` の IB-9）
- 例の名前: 母親＝お母さん、子供＝太郎・花子・次郎。お手伝い＝皿洗い（100 円）、風呂掃除（150 円）
- 機能以外の要件（NFR）は、関係するストーリーの受け入れ条件に入れています（Q1）

## 受け入れ条件の前提データ

受け入れ条件の Given にある担当の状態（「未」「済」「×」）、月の確定、「代わりにやる」で引き受けた担当、お知らせ先の登録は、テストのときにあらかじめ用意したデータで作ってよいものとします。そのため、各ストーリーは、その状態を作るストーリーができていなくても試せます。下の一覧の「前提となるストーリー」は、利用者がその機能を実際に使うときに先にできている必要があるストーリーで、テストの順番の制約ではありません。

| 前提データとして用意してよい状態 | その状態を作るストーリー | その状態を使う受け入れ条件 |
|----------------------------------|--------------------------|----------------------------|
| 担当が「済」 | US5.1、US6.1 | AC3.1.3、AC3.1.4、AC5.1.3、AC6.1.1、AC6.1.4 |
| 担当が「×」 | US6.1 | AC5.1.11、AC6.1.3、AC6.1.5 |
| 月が確定している | US6.1 | AC3.1.7、AC4.1.1、AC5.1.6、AC5.1.9、AC7.1.2、AC7.1.10、AC8.2.5、AC9.1.4、AC9.1.9 |
| 「代わりにやる」で引き受けた担当 | US7.1 | AC3.1.5 |
| お知らせ先が登録されている | US1.2 | AC7.1.1〜AC7.1.11、AC9.1.1〜AC9.1.10 |

## US1.1 家族を作って子供を招待する

**母親として、** 家族を作って子供を招待し、家族以外の人が使えないようにしたい。**なぜなら、** 家族のお手伝いとお小遣いの情報を家族の中だけで扱いたいから。

- 人物: 母親（作る・招待する）、子供（参加する）
- 優先度: Must Have
- 要件: FR1.1、FR1.2、FR1.3、FR1.4、FR1.6、FR1.7、NFR4

受け入れ条件:

- **AC1.1.1** Given まだ記録されていない利用者がいる / When 公式アカウントを友だち登録する / Then その人の LINE のユーザー ID と表示名が記録される（FR1.1）
- **AC1.1.2** Given すでに記録されている利用者がいる / When ブロックしてから友だち登録し直す / Then 記録は重複せず、同じ人として扱われる（FR1.1）
- **AC1.1.3** Given どの家族にも入っていない利用者がいる / When アプリを開く / Then 「家族を作る」と「招待を待つ」が表示される（FR1.2）
- **AC1.1.4** Given どの家族にも入っていない利用者がいる / When 「家族を作る」を選ぶ / Then 新しい家族ができ、その人が管理者になる（FR1.3）
- **AC1.1.5** Given すでに家族に入っている利用者がいる / When 「家族を作る」を実行しようとする / Then 2 つ目の家族は作られず、「すでに家族に入っています」と表示される（FR1.3）
- **AC1.1.6** Given 管理者がいる / When 招待用のリンクを作る / Then リンクが表示され、LINE で送れる（FR1.4）
- **AC1.1.7** Given 招待を待っている利用者がいる / When 招待用のリンクを開いて参加する / Then その人がその家族の子供になる（FR1.4）
- **AC1.1.8** Given ほかの家族に入っている利用者がいる / When 招待用のリンクを開く / Then 参加せず、「すでに別の家族に入っています」と表示される（FR1.4）
- **AC1.1.9** Given 招待用のリンクが無効になっている / When 開く / Then 参加せず、「この招待は使えません。管理者に新しい招待を頼んでください」と表示される（FR1.4）
- **AC1.1.10** Given 家族のメンバーがパソコンのブラウザでアプリを開く / When LINE にログインする / Then スマホと同じ家族のカレンダーが表示される（FR1.6）
- **AC1.1.11** Given ある家族のメンバーではない利用者がいる / When その家族のカレンダーやお小遣いを開こうとする / Then 中身は表示されず、「このアプリは家族のメンバーだけが使えます」と表示される（FR1.7、NFR4）
- **AC1.1.12** Given LINE の認証がない要求、ほかの家族のメンバーからの要求、または子供による管理者の操作（招待用のリンクを作る、お知らせ先の登録、お手伝いの種類の登録・変更、割り当ての保存・変更、記録の取り消し、済にする、やらなかったにする・外す、確定・確定の取り消し、加算・減額）の要求がある / When 裏側に届く / Then すべて断られる（NFR4、FR6.6）
- **AC1.1.13** Given 子供がいる / When 招待用のリンクを作ろうとする / Then 作れない（FR1.4、NFR4）

INVEST: 独立して試せる。家族を作る・招待する・参加する・断るの 4 つの流れを含むため大きめだが、ほかのストーリーの前提になるひとまとまりとして扱う。

## US1.2 家族のグループをお知らせ先にする

**母親として、** 公式アカウントを家族のグループ LINE に招待して、お知らせ先として登録したい。**なぜなら、** リマインドや月末のまとめを家族全員に届けたいから。

- 人物: 母親
- 優先度: Must Have
- 要件: FR1.5

受け入れ条件:

- **AC1.2.1** Given 管理者が公式アカウントをグループに招待した / When そのグループをお知らせ先として登録する / Then お知らせがそのグループに届き、代わりにやるの申し出がそのグループでできる（FR1.5）
- **AC1.2.2** Given すでにお知らせ先がある / When 管理者が別のグループを登録する / Then お知らせ先が新しいグループに置き換わり、前のグループには届かなくなる（FR1.5）
- **AC1.2.3** Given 子供がいる / When お知らせ先を登録しようとする / Then 登録できず、「お知らせ先を登録できるのは管理者だけです」と返事する（FR1.5）
- **AC1.2.4** Given お知らせ先がまだない / When 16 時や月末 21 時になる / Then 何も送らず、管理者がアプリを開くと「お知らせ先のグループが登録されていません」と表示される（FR1.5）
- **AC1.2.5** Given 登録されていないグループで公式アカウントに話しかけた / When 子供が代わりにやるの申し出をしようとする / Then 受け付けず、「このグループは家族のお知らせ先として登録されていません」と返事する（FR1.5）

INVEST: US1.1 の家族があれば、単独で試せる。

## US2.1 お手伝いの種類を決める

**母親として、** お手伝いの種類ごとに名前・単価・説明を決めたい。**なぜなら、** 家族に合ったお手伝いを、決まった単価で数えたいから。

- 人物: 母親
- 優先度: Must Have
- 要件: FR2.1、FR2.2、FR2.3、FR2.4

受け入れ条件:

- **AC2.1.1** Given 管理者がいる / When 名前「皿洗い」、単価 100 円、説明を入れて保存する / Then 種類の一覧に「皿洗い 100 円」が出る（FR2.1）
- **AC2.1.2** Given 管理者が単価に -1、小数、空欄を入れる / When 保存しようとする / Then 保存されず、「単価は 0 円以上の整数で入力してください」と表示され、入力した内容は残る（FR2.1）
- **AC2.1.3** Given 子供がいる / When 種類を登録・変更しようとする / Then できない（FR2.1）
- **AC2.1.4** Given 皿洗いが 100 円で記録が 3 回ある / When 単価を 120 円に変え、そのあと 1 回記録される / Then 皿洗いの金額は 420 円になる（FR2.2）
- **AC2.1.5** Given 皿洗いを「使わない」にした / When 月の割り当てを開く / Then 皿洗いは選べず、過去の記録とお小遣いはそのまま表示される（FR2.3）
- **AC2.1.6** Given 割り当てに使われたことがある種類がある / When 消そうとする / Then 消せず、「使わない」にするよう案内される（FR2.4）
- **AC2.1.7** Given 割り当てに一度も使われていない種類がある / When 消す / Then 一覧から完全になくなる（FR2.4）

INVEST: 単独で試せる。

## US3.1 月の割り当てを入力する

**母親として、** 家族で話し合って決めた 1 か月分の割り当てを、お手伝いごとに子供と曜日を選んで入力し、必要な日だけ直したい。**なぜなら、** 1 日ずつ入力する手間をかけずに、月の担当を決めたいから。

- 人物: 母親
- 優先度: Must Have
- 要件: FR3.1、FR3.2、FR3.3、FR3.4、FR3.5

受け入れ条件:

- **AC3.1.1** Given 2027 年 1 月で、皿洗いを太郎の月曜・木曜に選んだ / When 保存する / Then 1 月のすべての月曜と木曜に「皿洗い=太郎」の担当ができる（FR3.1）
- **AC3.1.2** Given 1 月 20 日の皿洗いが太郎で「未」 / When 管理者が担当を花子に変える / Then 1 月 20 日の皿洗いの担当が花子になる（FR3.2）
- **AC3.1.3** Given 1 月 5 日の皿洗いが「済」 / When 管理者が担当を変えようとする / Then 変更できず、「記録を取り消してから変更してください」と表示される（FR3.2）
- **AC3.1.4** Given 今日は 1 月 10 日、1 月 5 日は「済」、1 月 20 日は日ごとに変更済み / When 月の割り当てを保存し直す / Then 1 月 5 日と 1 月 10 日は変わらず、1 月 20 日は作り直した内容になる（FR3.3）
- **AC3.1.5** Given 1 月 22 日の皿洗いを太郎が花子から引き受けていた / When 月の割り当てを保存し直す / Then 保存の前に「1月22日 皿洗い: 太郎 → 花子」が確認として表示され、確認すると作り直した内容になる（FR3.3）
- **AC3.1.6** Given 皿洗いを太郎の月曜と花子の月曜に選んだ / When 保存しようとする / Then 保存されず、「1月4日(月) の皿洗いに担当が 2 人います」のように重なりがすべて表示される（FR3.4）
- **AC3.1.7** Given 1 月が確定している / When 管理者が 1 月の割り当てを保存し直す、または日ごとの担当を変えようとする / Then 変更できず、「この月は確定済みです」と表示される（FR3.5）
- **AC3.1.8** Given 子供がいる / When 月の割り当てを保存する、または日ごとの担当を変えようとする / Then できない（NFR4）

INVEST: US2.1 の種類があれば試せる。「済」「確定」「引き受けた担当」は前提データで用意する（受け入れ条件の前提データ）。

## US4.1 カレンダーで担当を見る

**母親・子供として、** 今月のカレンダーで、家族全員の担当と状態を見たい。**なぜなら、** だれがいつ何をやるか、やったかどうかをすぐに知りたいから。

- 人物: 母親、子供
- 優先度: Must Have
- 要件: FR4.1、FR4.2、FR4.3、FR4.4、FR4.5、NFR7、NFR9

受け入れ条件:

- **AC4.1.1** Given 1 月 2 日の皿洗い（太郎）が「済」 / When アプリを開く / Then 最初に今月のカレンダーが表示され、1 月 2 日に「皿洗い=太郎(済)」と文字で表示される。確定している月には「確定済み」と表示される（FR4.1、NFR9）
- **AC4.1.2** Given 太郎が 1 月 2 日 16:42 に皿洗いを記録した / When 1 月 2 日を開く / Then 「済 16:42 太郎が記録」と表示される（FR4.2）
- **AC4.1.3** Given 花子がいる / When カレンダーとお小遣いを開く / Then 太郎と次郎の担当とお小遣い額も表示される（FR4.3）
- **AC4.1.4** Given 2 月の割り当てがまだない / When 管理者が 2 月を開く / Then 「この月の割り当てはまだありません」と、割り当ての画面へ進むボタンが表示される。子供が開いたときはボタンは表示されない（FR4.4）
- **AC4.1.5** Given 裏側に一時的につながらない / When カレンダーを開く / Then 「表示できませんでした。もう一度お試しください」と「読み込み直す」ボタンが表示され、つながってから押すとカレンダーが表示される（FR4.5）
- **AC4.1.6** Given ステージングで家族 4 人分のデータがある / When カレンダーを 20 回開く / Then 19 回以上が 3 秒以内に表示される（NFR7）
- **AC4.1.7** Given アプリのすべての画面（カレンダー、日の詳細、お手伝いの種類、月の割り当て、お小遣い、加算・減額、確認の表示、家族を作る・参加する画面）がある / When 文字と背景の色、押す場所の大きさ、状態の表し方を確かめる / Then 色の差は 4.5:1 以上、押す場所は 44×44 ピクセル以上で、状態は色だけでなく文字でも表されている（NFR9）

INVEST: US3.1 の担当があれば、単独で試せる。

## US5.1 やったお手伝いを記録する

**子供として、** お手伝いが終わったら、LINE のメニューからすぐ記録したい。記録し忘れたら、あとから画面で記録したい。**なぜなら、** やった分のお小遣いを正しく数えてもらいたいから。

- 人物: 子供
- 優先度: Must Have
- 要件: FR5.1〜FR5.8、NFR11

受け入れ条件:

- **AC5.1.1** Given 太郎に今日の皿洗い（未）がある / When 1 対 1 のトークのリッチメニューで「やった」をタップし、「皿洗い」を選ぶ / Then 皿洗いが「済」になり、記録した時刻が保存される（FR5.1）
- **AC5.1.2** Given 太郎が 16:42 に記録した / When 記録が終わる / Then 太郎との 1 対 1 のトークに「皿洗いを記録しました（16:42）」と返事が届き、お知らせ先のグループには何も届かない（FR5.2）
- **AC5.1.3** Given 太郎の皿洗いがすでに「済」 / When 「やった」をタップする / Then 皿洗いは選べない状態で表示される（FR5.3）
- **AC5.1.4** Given 太郎が同じ担当の記録ボタンを短い間に 2 回押した / When 2 回目が届く / Then 記録は 1 件のままになる（FR5.3）
- **AC5.1.5** Given 太郎に今日記録できる担当がない / When 「やった」をタップする / Then 「今日記録できる担当はありません」と返事する（FR5.4）
- **AC5.1.6** Given 今月が確定している / When 太郎が「やった」をタップする / Then 「この月は確定済みです」と返事し、記録しない（FR5.4）
- **AC5.1.7** Given 太郎が 1 月 5 日の皿洗いを記録し忘れ、1 月は確定していない / When 1 月 7 日にアプリから記録する / Then 1 月 5 日の皿洗いが「済」になり、記録した時刻（1 月 7 日）が保存される。LINE のお知らせは送られない（FR5.5）
- **AC5.1.8** Given 今日は 2 月 1 日で、1 月は確定していない / When 太郎が 1 月 31 日の自分の担当を記録する / Then 記録できる（FR5.5）
- **AC5.1.9** Given 1 月が確定している / When 太郎が 1 月の担当を画面から記録しようとする / Then 記録できず、「この月は確定済みです」と表示される（FR5.5）
- **AC5.1.10** Given 今日は 1 月 7 日 / When 太郎が 1 月 8 日の担当を記録しようとする / Then 記録できず、「まだ来ていない日の担当は記録できません」と表示される（FR5.5）
- **AC5.1.11** Given 1 月 5 日の太郎の皿洗いが「×」 / When 太郎が記録しようとする / Then 記録できず、「お母さんが『やらなかった』にしています」と表示される（FR5.6）
- **AC5.1.12** Given 花子の担当がある / When 太郎がその担当を記録しようとする / Then 記録できない（FR5.7）
- **AC5.1.13** Given 太郎の皿洗い（100 円）が 3 回 / When 1 回記録する / Then すぐにお小遣いの画面で 4 回・400 円と表示される（FR5.8）
- **AC5.1.14** Given 日本時間の 1 月 7 日 23:59 と 1 月 8 日 0:00 に、それぞれその日の担当を記録した / When 記録を確かめる / Then それぞれ 1 月 7 日と 1 月 8 日の記録として扱われる（NFR11）
- **AC5.1.15** Given ステージングで家族 4 人分のデータがある / When リッチメニューの「やった」から担当を選んで記録する操作を 20 回行う / Then 19 回以上で、3 秒以内に「記録しました」の返事が届く（NFR7）

INVEST: US3.1 の担当があれば試せる。「×」「確定」は前提データで用意する（受け入れ条件の前提データ）。リッチメニューと画面の 2 つの入り口を含むため大きめ。

## US6.1 記録を確認・修正し、月を確定する

**母親として、** 子供の記録を確認して、間違いを直し、終わった月を確定したい。確定を間違えたら取り消したい。**なぜなら、** お小遣いの金額を正しくし、確定した金額をそのまま残したいから。

- 人物: 母親
- 優先度: Must Have
- 要件: FR6.1〜FR6.6、NFR6

担当の状態の変わり方は、requirements の FR6.1 の表のとおりです。

受け入れ条件:

- **AC6.1.1** Given 太郎の 1 月 5 日の皿洗いが「済」 / When 管理者が取り消しを選び、確認する / Then 「未」になり、回数から外れる（FR6.1、FR6.2）
- **AC6.1.2** Given 単価 120 円で、太郎の 1 月 5 日の皿洗いが「未」 / When 管理者が 1 月 7 日 20:00 に「済にする」を選ぶ / Then 「済 1/7 20:00 お母さんが記録」と表示され、120 円として数えられる（FR6.1、FR6.3）
- **AC6.1.3** Given 太郎の 1 月 5 日の皿洗いが「×」 / When 管理者が「済にする」を選ぶ / Then 「済」になり、回数に数えられる（FR6.1、FR6.3）
- **AC6.1.4** Given 太郎の 1 月 5 日の皿洗いが「済」 / When 管理者が「やらなかったにする」を選び、確認する / Then 「×」になり、記録は消え、回数から外れる（FR6.1、FR6.4）
- **AC6.1.5** Given 太郎の 1 月 5 日の皿洗いが「×」 / When 管理者が「やらなかったを外す」を選び、確認する / Then 「未」に戻り、太郎がまた記録できる（FR6.1、FR6.4）
- **AC6.1.6** Given 1 月が確定していない / When 管理者が 1 月 20 日に 1 月を確定する / Then 1 月が確定済みとして表示され、それ以降の 1 月の記録・取り消し・状態の変更・割り当ての変更はすべて断られる（FR6.5）。加算・減額が断られることは US8.2 の AC8.2.5 で確かめる
- **AC6.1.7** Given 1 月が確定している / When 管理者が確定を取り消す / Then 「確定済み」の表示が消え、また 1 月の記録と修正ができる（FR6.5）
- **AC6.1.8** Given 2026 年 12 月を確定しないまま 2027 年 3 月になった / When 太郎が 12 月 28 日の自分の「未」の担当を記録する / Then 記録できる（FR6.5）
- **AC6.1.9** Given 取り消し・やらなかった・確定・確定の取り消しのどれかを選んだ / When 操作する / Then 実行の前に、何が変わるかを書いた確認が表示される（FR6.2、FR6.4、FR6.5）
- **AC6.1.10** Given 太郎がいる / When 記録を取り消す、済にする、やらなかったにする、やらなかったを外す、確定する、確定を取り消すのどれかをしようとする / Then どれもできない（FR6.6、NFR4）
- **AC6.1.11** Given FR6.1 の表のすべての変わり方と、確定・確定の取り消しがある / When アプリの画面から操作する / Then データを直接書き換えなくても、すべての間違いを直せる（NFR6）

INVEST: US3.1 の担当があれば試せる。「済」「×」は前提データで用意する（受け入れ条件の前提データ）。状態の変わり方と確定をまとめて扱うため大きめ。

## US7.1 担当を代わってもらう

**子供として、** 都合が悪い日の担当を、家族のグループでほかの子供に代わってもらいたい。**なぜなら、** 母親に頼まなくても、子供どうしで担当を調整したいから。

- 人物: 子供
- 優先度: Must Have
- 要件: FR7.1〜FR7.5

受け入れ条件:

- **AC7.1.1** Given 花子に 1 月 8 日の皿洗い（未）がある / When お知らせ先のグループで「代わって」と送る / Then 返事として「1/8 皿洗い」のボタンが表示される（FR7.1）
- **AC7.1.2** Given 1 月が確定していて、花子の今日以降の担当は 1 月にしかない / When 「代わって」と送る / Then 「この月は確定済みです」と返事し、ボタンは出ない（FR7.1）
- **AC7.1.3** Given 花子に今日以降の「未」の担当がなく、今月は確定していない / When 「代わって」と送る / Then 「申し出られる担当はありません」と返事する（FR7.1）
- **AC7.1.4** Given 花子が「1/8 皿洗い」を選んだ / When 選ぶ / Then グループに返事として「花子が 1月8日 の皿洗いを代わってくれる人を探しています」と、「引き受ける」「申し出をやめる」のボタンが表示される（FR7.2）
- **AC7.1.5** Given 花子の申し出がある / When 太郎が「引き受ける」を押す / Then 1 月 8 日の皿洗いの担当が太郎になり、太郎の自分の担当は動かず、「太郎が 1月8日 の皿洗いを引き受けました」と返事が届く（FR7.3）
- **AC7.1.6** Given 太郎がすでに引き受けた / When 次郎が「引き受ける」を押す / Then 担当は変わらず、「この申し出はもう引き受けられています」と返事する（FR7.3）
- **AC7.1.7** Given 花子の申し出がある / When 花子本人か管理者が「引き受ける」を押す / Then 担当は変わらず、「この申し出には応えられません」と返事する（FR7.3）
- **AC7.1.8** Given 花子の申し出がまだ引き受けられていない / When 花子が「申し出をやめる」を押す / Then 申し出がなくなり、そのあと「引き受ける」を押すと「この申し出はもうありません」と返事する（FR7.4）
- **AC7.1.9** Given 花子の 1 月 8 日の皿洗いにすでに申し出がある / When 花子が同じ担当をもう一度申し出る / Then 「この担当はもう申し出ています」と返事する（FR7.5）
- **AC7.1.10** Given 花子の申し出がある / When 管理者が 1 月 8 日の皿洗いの担当を次郎に変える、その日が過ぎる、担当の状態が「未」でなくなる、1 月が確定される、のどれかが起きる / Then 申し出はなくなる（FR7.5）
- **AC7.1.11** Given ステージングで家族 4 人分のデータがある / When 「代わって」「担当のボタン」「引き受ける」の操作を合わせて 20 回行う / Then 19 回以上で、3 秒以内に返事が届く（NFR7）

INVEST: US3.1 の担当があれば試せる。お知らせ先と「確定」は前提データで用意する（受け入れ条件の前提データ）。

## US8.1 お小遣いの額を見る

**母親・子供として、** 子供ごとの今月のお小遣いの額を、内訳つきで見たい。**なぜなら、** どのお手伝いを何回やって、いくらになったかを家族で確かめたいから。

- 人物: 母親、子供
- 優先度: Must Have
- 要件: FR8.1、FR8.3

受け入れ条件:

- **AC8.1.1** Given 太郎の 1 月に、皿洗い 100 円が 8 回、風呂掃除 150 円が 4 回ある / When お小遣いの画面を開く / Then 800 円・600 円の内訳と、合計 1,400 円が表示される（FR8.1）
- **AC8.1.2** Given 次郎の 1 月の記録がまだない / When お小遣いの画面を開く / Then 「今月の記録はまだありません（0 円）」と表示される（FR8.1）
- **AC8.1.3** Given 太郎の 1 月の皿洗い（100 円）が 3 回 / When 画面を開く / Then 金額はすべて円の整数で表示される（FR8.3）。合計がマイナスになるのは減額があるときだけなので、マイナスの表示は US8.2 の AC8.2.6 で確かめる
- **AC8.1.4** Given 単価が月の途中で変わった / When お小遣いの画面を開く / Then 記録ごとに、記録が付いた時点の単価で計算した額が合計される（FR8.1）

INVEST: US5.1 の記録があれば、単独で試せる。

## US8.2 お小遣いを加算・減額する

**母親として、** 理由を書いて、子供のお小遣いを加算・減額したい。**なぜなら、** お手伝いの回数だけでは表せない、がんばりや約束やぶりを金額に反映したいから。

- 人物: 母親
- 優先度: Should Have（遅れた場合は最初の版から外してよい）
- 要件: FR8.2

受け入れ条件:

- **AC8.2.1** Given 管理者がいる / When 太郎に「減額 200 円、理由: 片付けをしなかった」を入れて保存する / Then 太郎のお小遣いの内訳に「-200 円（片付けをしなかった）」が加わる（FR8.2）
- **AC8.2.2** Given 管理者が理由を空欄にする / When 保存しようとする / Then 保存されず、「理由を入力してください」と表示され、入力した内容は残る（FR8.2）
- **AC8.2.3** Given 管理者が金額に 0、マイナス、小数を入れる / When 保存しようとする / Then 保存されず、「金額は 1 円以上の整数で入力してください」と表示される（FR8.2）
- **AC8.2.4** Given 子供がいる / When 加算・減額を入れようとする / Then できない（FR8.2、NFR4）
- **AC8.2.5** Given 1 月が確定している / When 管理者が 1 月の加算・減額を入れる、または消そうとする / Then できず、「この月は確定済みです」と表示される（FR6.5）
- **AC8.2.6** Given 太郎の 1 月に、皿洗い 100 円が 8 回、風呂掃除 150 円が 4 回、減額 200 円がある / When お小遣いの画面を開く / Then 800 円・600 円・-200 円の内訳と、合計 1,200 円が表示される（FR8.1、FR8.2）
- **AC8.2.7** Given 次郎の 1 月は記録 1 回 100 円と減額 300 円 / When お小遣いの画面を開く / Then 合計は -200 円と表示され、0 円にそろえない（FR8.3）

INVEST: US8.1 があれば、単独で試せる。外しても、ほかのストーリーは成り立つ。

## US9.1 リマインドと月末のまとめを受け取る

**母親・子供として、** 毎日 16 時にその日の担当を、月末にお小遣いのまとめを、家族のグループで受け取りたい。**なぜなら、** 担当を忘れずに取り掛かり、月の結果を家族で共有したいから。

- 人物: 母親、子供
- 優先度: Must Have
- 要件: FR9.1〜FR9.5、NFR1、NFR2、NFR11

受け入れ条件:

- **AC9.1.1** Given 今日、家族の誰かに担当がある / When 日本時間の 16 時になる / Then その日の担当の一覧が 1 通届く（FR9.1、NFR11）
- **AC9.1.2** Given 今日、誰にも担当がない / When 16 時になる / Then 何も送らない（FR9.1）
- **AC9.1.3** Given 今日のリマインドはすでに送った / When 送信の処理がもう一度動く / Then 2 通目は送らない（FR9.1）
- **AC9.1.4** Given 今月がすでに確定している / When 16 時になる / Then リマインドは送らない。確定を取り消したあとは、また送る（FR9.1）
- **AC9.1.5** Given 1 月 31 日 21 時になった / When まとめを送る / Then 「1月のお小遣い 太郎 1,200円 / 花子 900円 / 次郎 600円」が 1 通届く（FR9.2）
- **AC9.1.6** Given 1 月のまとめを送ったあと、1 月は確定していない / When 管理者が 1 月 31 日の記録を取り消す / Then アプリの 1 月の金額は新しい金額になり、まとめは送り直さない（FR9.3）
- **AC9.1.7** Given 1 か月がたった / When その月に送った返事ではないお知らせを数える / Then 最大で 31 通 + 1 通になり、4 人のグループで月 128 通以内に収まる（FR9.4、NFR1）
- **AC9.1.8** Given 16 時のリマインド、または月末 21 時のまとめの送信に失敗した / When 15 分たつ / Then 作り手に失敗の知らせが届いていて、同じお知らせは二重に届いていない（FR9.5、NFR2）
- **AC9.1.9** Given 1 月がすでに確定している / When 1 月 31 日 21 時になる / Then 1 月のまとめは 1 通届く。まとめは確定していてもいなくても送る（FR6.5、FR9.2）
- **AC9.1.10** Given 1 月のまとめはすでに送った / When 送信の処理がもう一度動く / Then 2 通目は送らない（FR9.2）

INVEST: US3.1 の担当と US8.1 の金額があれば試せる。お知らせ先と「確定」は前提データで用意する（受け入れ条件の前提データ）。

## あとの段階で決めること

要件にまだ書かれていない、細かい場合の扱いです。あとの「機能設計（functional-design）」の段階で決めます。

- 管理者が、お知らせ先のグループで「代わって」と送ったときの返事（US7.1）
- 子供が、公式アカウントとの 1 対 1 のトークで「代わって」と送ったときの返事（US7.1）
- 公式アカウントを友だち登録していない利用者がアプリを開いたときの表示（US1.1）

## INVEST についての注意

Q3 で、ストーリーを要件のまとまりごとに 1 つにすると決めたため、US1.1、US5.1、US6.1 は受け入れ条件が 10 を超えて大きめです。実際に作るときの作業の単位は、このあとの「作業単位の分割」の段階で分けます。
