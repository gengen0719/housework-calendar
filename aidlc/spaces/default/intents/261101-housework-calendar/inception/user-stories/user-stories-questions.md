# ユーザーストーリー — ストーリーの計画と質問

要件（`inception/requirements-analysis/requirements.md`）を、利用者の目線のストーリーに書き直します。ストーリーには「〜として、〜したい。なぜなら〜だから」の形と、Given/When/Then の受け入れ条件を付けます（`team-practices.md` の BDD）。要件の中身はもう決まっているので、ここで決めるのは、ストーリーの分け方と細かさだけです。

## 計画（案）

- **人物像:** 母親（管理者）と子供の 2 つを基本にする（Q1 で決める）
- **書き方:** INVEST（ほかと独立している、話し合える、価値がある、見積もれる、小さい、テストできる）を満たすように書く
- **優先度:** 要件の作業一覧（`ideation/scope-definition/intent-backlog.md`）に合わせ、加算・減額（IB-9）だけを Should Have、ほかは Must Have にする
- **分け方と細かさ:** Q2・Q3 で決める
- **ID:** ストーリーは `US{まとまり}.{番号}`、受け入れ条件は `AC{まとまり}.{番号}.{番号}` とし、要件の `FR` / `NFR` と対応表で結ぶ
