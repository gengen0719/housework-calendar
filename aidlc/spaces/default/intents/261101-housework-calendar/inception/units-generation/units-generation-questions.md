# 作業単位の分割 — 質問

ドメイン設計で決めた 7 つの部品（`inception/domain-design/components.md`）を、実際に作って確かめる「作業単位（ユニット）」にまとめます。ここで決めるのは、単位の分け方、単位どうしの頼り方（どれがどれに頼るか）、配備の形です。どの単位から作るか（順番）は、次の次の「作る順の計画（delivery-planning）」で決めます。

前提として、チームの決まり（`aidlc/spaces/default/memory/team.md`）で、最初に端から端まで通る最小限の形（walking skeleton）を作ることが決まっています。そのため、最初の単位は「LINE でログインする → 画面を開く → 裏側の処理を呼ぶ → データを保存する → 公式アカウントが返事をする」が最小限でつながる形にします。

## 案（質問の前提）

ストーリーの「使う流れの順」に沿って、画面と裏側をまとめて縦に切る案を考えています。

| 単位 | 中身 | 関わるストーリー |
|------|------|----------------|
| U1 最初の形（walking skeleton）と家族 | AWS への配備の土台、LINE ログインで画面を開く、家族を作る、招待、友だち登録の返事 | US1.1 |
| U2 お知らせ先 | 家族のグループを公式アカウントのお知らせ先にする | US1.2 |
| U3 お手伝いの種類 | 名前・単価・説明、使わない、消す | US2.1 |
| U4 割り当てとカレンダー | 月の割り当て、日ごとの担当、カレンダーの表示 | US3.1、US4.1 |
| U5 記録 | リッチメニューと画面からの「やった」 | US5.1 |
| U6 確認・修正と確定 | 状態の変更、月の確定と取り消し | US6.1 |
| U7 代わりにやる | グループでの申し出・引き受け・取り下げ | US7.1 |
| U8 お小遣い | 額の計算と内訳、加算・減額 | US8.1、US8.2 |
| U9 お知らせ | 16 時のリマインド、月末 21 時のまとめ | US9.1 |

C. 配備先ごとに分ける（裏側、画面、AWS の構成の 3 つ）
