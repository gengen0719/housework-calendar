# 画面の詳細（Mockups）

最初の版の画面と LINE のトークを、ストーリーごとに細かく描いたものです。もとにしたのは次の書類と回答です。

- ラフな画面イメージ（`ideation/rough-mockups/wireframes.md`、`ideation/rough-mockups/user-flow.md`）
- ユーザーストーリー（`inception/user-stories/stories.md`）
- 要件（`inception/requirements-analysis/requirements.md`）
- 進め方（`inception/practices-discovery/team-practices.md`）
- このステージの回答（`refined-mockups-questions.md` の Q1〜Q5）

色と部品は `design-system-mapping.md`、操作の決まり（確認、短い知らせ、間違えたときの直し方）は `interaction-spec.md`、見やすさの確かめ方は `accessibility-checklist.md` にまとめています。

承認の前に、「元に戻すは母親の操作だけかと思っていたよ、別につけなくてもいいよ」との指示を受けて、「元に戻す」ボタンはどの画面にも付けないことにしました。Q4 で選んだ短い知らせは残します。間違いは、母親が状態を変える操作（取り消す、済にする、やらなかったを外すなど）で直します。

## ラフな画面イメージから変わったこと

| もとの決定（`wireframes.md`） | この書類で（理由） |
|------------------------------|-------------------|
| 子供同士の「交換」 | 「代わりにやる」だけにする（`requirements.md` の FR7） |
| 家族の登録の画面がない | S0（はじめての画面）、S0b（招待の画面）、S7（家族の設定）を足す（`stories.md` の US1.1・US1.2） |
| 日の詳細で、管理者は「取り消し」「やらなかった」だけ | 「済にする」「やらなかったを外す」を足す（`requirements.md` の FR6.1） |
| 確定の操作がない | S5 に「この月を確定する」「確定を取り消す」を足す（`requirements.md` の FR6.5） |
| パソコンはスマホと同じ縦長、カレンダーだけ 7 列 | カレンダーと月の割り当ての 2 つを横に広げる（Q3） |
| 加算・減額は入れるだけ | S5 の加算・減額の行に、管理者だけが使える「消す」を足す（`stories.md` の AC8.2.5） |

## S0. はじめての画面（US1.1）

どの家族にも入っていない人がアプリを開いたときの画面です（`requirements.md` の FR1.2）。

```
+--------------------------------------+
| お手伝いカレンダーへようこそ          |  h1
|                                      |
| 家族のお手伝いとお小遣いを            |
| 記録するアプリです。                  |
|                                      |
| [ 家族を作る ]          (主なボタン)  |
|   お母さんなど、家族をまとめる人向け  |
|                                      |
| [ 招待を待つ ]          (ほかのボタン)|
|   招待のリンクが届いたら開いてください|
+--------------------------------------+
```

- 「家族を作る」を押すと確認なしで家族ができ、押した人が管理者になる。S7（家族の設定）へ進み、「次は家族を招待しましょう」と表示する（FR1.3）
- 「招待を待つ」を押すと「招待のリンクが届いたら、そのリンクを開いてください」と表示する
- すでに家族に入っている人がこの画面の操作をしたときは、「すでに家族に入っています」と表示してカレンダーへ進む（FR1.3）
- 家族のメンバーではない人が、ほかの家族の画面を開こうとしたときは「このアプリは家族のメンバーだけが使えます」と表示する（FR1.7）
- 公式アカウントを友だち登録していない人がアプリを開いたときの表示は、設計の段階（functional-design）で決める（`stories.md` の「あとの段階で決めること」）

## S0b. 招待の画面（US1.1）

招待用のリンクを開いたときの画面です（FR1.4）。

```
+--------------------------------------+
| 家族に参加する                        |  h1
|                                      |
| お母さんの家族に招待されています。    |
|                                      |
| [ 参加する ]            (主なボタン)  |
+--------------------------------------+
```

| 場合 | 表示 |
|------|------|
| 参加できる | 「参加する」を押すと子供として参加し、カレンダーへ進む。「家族に参加しました」と短い知らせを出す |
| ほかの家族に入っている | 「すでに別の家族に入っています」と表示し、「参加する」を出さない |
| リンクが無効 | 「この招待は使えません。管理者に新しい招待を頼んでください」と表示する |

## S1. カレンダー（ホーム、US4.1）

アプリを開くと最初に出る画面です（`wireframes.md` の Q2）。

スマホ（子供の太郎が見ている場合）:

```
+--------------------------------------+
| [<] 2027年1月 [>]                    |  h1（月の切り替え）
| (確定している月は「確定済み」を表示)   |
+--------------------------------------+
| 1月4日(月)                           |  h2
|  ##皿洗い = 太郎  未##   <- 自分の担当 |
|   風呂掃除 = 花子  済 16:42           |
| 1月5日(火)                           |
|   洗濯たたみ = 次郎  ×                |
| ...                                  |
+--------------------------------------+
| 今月のお小遣い（ここまで）            |
| 太郎 1,200円 / 花子 900円 / 次郎 600円|
+--------------------------------------+
| [カレンダー]  [お小遣い]              |  下のタブ
+--------------------------------------+
```

`##...##` は、自分の担当を太字と緑の枠で目立たせることを表す（Q5）。

パソコン（母親が見ている場合）:

```
+--------------------------------------------------------------+
| [<] 2027年1月 [>]                               [割り当て]   |
+--------+--------+--------+--------+--------+--------+--------+
| 月     | 火     | 水     | 木     | 金     | 土     | 日     |
+--------+--------+--------+--------+--------+--------+--------+
|        |        |        |        | 1      | 2      | 3      |
|        |        |        |        | 皿洗い | 皿洗い |        |
|        |        |        |        | 太郎 済| 花子 済|        |
+--------+--------+--------+--------+--------+--------+--------+
| 4      | 5      | ...                                        |
+--------+--------+--------------------------------------------+
| 今月のお小遣い（ここまで） 太郎 1,200円 / 花子 900円 / 次郎 600円 |
+--------------------------------------------------------------+
| [カレンダー]  [お小遣い]  [設定]                              |
+--------------------------------------------------------------+
```

- 日ごとに、お手伝い・担当の子供・状態を表示する。状態は「済」「未」「×」の文字で表す（FR4.1）
- 「済」には記録した時刻を添える（FR4.2）
- 家族全員の担当とお小遣い額を、子供も見られる（FR4.3）
- 日付を選ぶと S2 を開く
- スマホは週ごとの縦の一覧で、今日の週から表示する。パソコンは 7 列の表で 1 か月を 1 画面に表示する（Q3）
- 割り当てがない月は「この月の割り当てはまだありません」と表示する。管理者には「割り当てを入力する」ボタンも出す（FR4.4）
- 読み込み中は枠だけを表示する。失敗したときは「表示できませんでした。もう一度お試しください」と「読み込み直す」を出す（FR4.5）
- お知らせ先のグループがまだ登録されていないときは、管理者にだけ、上に「お知らせ先のグループが登録されていません」と S7 へのリンクを出す（FR1.5）

## S2. 日の詳細（US5.1、US6.1、US3.1）

管理者が見ている場合:

```
+--------------------------------------+
| [<戻る]  1月5日(火)                   |  h1
+--------------------------------------+
| 皿洗い  担当: 太郎                    |  h2
|   未                                  |
|   [済にする] [やらなかったにする]       |
|   [担当を変える v]                     |
+--------------------------------------+
| 風呂掃除  担当: 花子                  |  h2
|   済  1/7 16:00 花子が記録（あとから） |
|   [記録を取り消す] [やらなかったにする] |
+--------------------------------------+
| 洗濯たたみ  担当: 次郎                |  h2
|   ×  やらなかった                     |
|   [済にする] [やらなかったを外す]       |
+--------------------------------------+
```

子供（太郎）が見ている場合:

```
+--------------------------------------+
| [<戻る]  1月5日(火)                   |
+--------------------------------------+
| ##皿洗い  担当: 太郎##                |
|   未                                  |
|   [記録する]                          |
+--------------------------------------+
| 風呂掃除  担当: 花子                  |
|   済  1/7 16:00 花子が記録（あとから） |
+--------------------------------------+
| 洗濯たたみ  担当: 次郎                |
|   ×  お母さんが「やらなかった」にしています |
+--------------------------------------+
```

- 状態ごとに出すボタンは `interaction-spec.md` の「担当の行」のとおり（`requirements.md` の FR6.1）
- 子供は、確定していない月の、今日までの自分の「未」の担当だけを記録できる。明日以降の担当には「記録する」を出さない（FR5.5）
- 担当の日とは違う日に記録したもの、管理者が「済にする」を付けたものには「（あとから）」を添える。取り掛かった時刻と区別できるようにするため（`requirements.md` の目的の整理）
- 取り消し・やらなかったにする・やらなかったを外すは、確認の小窓を出す（FR6.2・FR6.4）
- 「担当を変える」は「未」の担当だけに出す。「済」の担当では「記録を取り消してから変更してください」と表示する（FR3.2）
- 確定している月では、ボタンを出さず「この月は確定済みです」と表示する（FR6.5）
- 操作のあとは短い知らせを出す。「元に戻す」は付けない。間違えたときの直し方は `interaction-spec.md` のとおり（Q4、承認前の指示）

## S3. お手伝いの種類（管理者のみ、US2.1）

```
+--------------------------------------+
| お手伝いの種類            [+ 追加]    |  h1
+--------------------------------------+
| 皿洗い    100円               [編集]  |
| 風呂掃除  150円               [編集]  |
| 窓ふき    80円   使わない      [編集]  |
+--------------------------------------+

(編集)
+--------------------------------------+
| お手伝いの種類を編集                  |  h1
| 名前                                  |
| [ 皿洗い                         ]    |
| 単価（円）                            |
| [ 100 ]                               |
|   単価を変えると、これから記録する分  |
|   から新しい単価になります            |
| 説明                                  |
| [ 食器を洗って水切りかごに並べたら完了 ] |
| [ ] 使わない                          |
| [保存]  [やめる]                      |
| [この種類を消す]  (使われたことがない種類のみ) |
+--------------------------------------+
```

- 名前・単価・説明を設定する（FR2.1）
- 単価の欄の下に、変更が「これから記録する分から」効くことを書く（FR2.2）
- 「使わない」にした種類は一覧に「使わない」と表示し、割り当てでは選べない（FR2.3）
- 「この種類を消す」は、割り当てに使われたことがない種類にだけ出す。使われたことがある種類では「使わない」にするよう案内する（FR2.4）
- 単価が 0 以上の整数でないときは、欄のすぐ下に「単価は 0 円以上の整数で入力してください」と出し、入力した内容は残す（FR2.1）
- 種類がないときは「お手伝いの種類がありません。最初の種類を追加しましょう」と「追加」ボタンを出す

## S4. 月の割り当て（管理者のみ、US3.1）

スマホ:

```
+--------------------------------------+
| [<] 2027年1月の割り当て [>]          |  h1
+--------------------------------------+
| 皿洗い                                |  h2
|  担当 [太郎 v]                        |
|   [x]月 [ ]火 [ ]水 [x]木 [ ]金 [ ]土 [ ]日 |
|  担当 [花子 v]                        |
|   [ ]月 [x]火 [ ]水 [ ]木 [x]金 [ ]土 [ ]日 |
|  [+ 担当を追加]                       |
+--------------------------------------+
| 風呂掃除                              |  h2
|  ...                                  |
+--------------------------------------+
| [保存]                                |
+--------------------------------------+
```

パソコン（Q3）:

```
+--------------------------------------------------------------+
| [<] 2027年1月の割り当て [>]                                   |
+------------+------+------+------+------+------+------+------+
| お手伝い   | 月   | 火   | 水   | 木   | 金   | 土   | 日   |
+------------+------+------+------+------+------+------+------+
| 皿洗い     | 太郎 | 花子 |  -   | 太郎 | 花子 |  -   |  -   |
| 風呂掃除   | 次郎 |  -   | 次郎 |  -   |  -   | 花子 |  -   |
+------------+------+------+------+------+------+------+------+
| [保存]                                                       |
+--------------------------------------------------------------+
```

パソコンでは、お手伝いと曜日のマスごとに担当の子供を選ぶ。スマホと同じ内容を、1 画面で見られる形にしたもの。

- 保存すると、その月の日ごとの担当ができる（FR3.1）
- 同じ日の同じお手伝いに担当が 2 人入るときは保存できず、「1月4日(月) の皿洗いに担当が 2 人います」のように、重なりをすべて画面の上に一覧で出す（FR3.4）
- 保存し直すときに上書きされる担当（日ごとに変えたもの、代わりにやるで引き受けたもの）があれば、保存の前に確認の小窓で一覧を見せる。例: 「1月22日 皿洗い: 太郎 → 花子」（FR3.3）
- 作り直すのは明日以降の「未」の担当だけ。今日と過ぎた日、「済」「×」の担当は変えない（FR3.3）
- 「使わない」の種類は表示しない（FR2.3）
- 確定している月は「この月は確定済みです」と表示し、保存できない（FR3.5）
- 前の月のコピーや自動の割り当ては付けない（`ideation/scope-definition/scope-document.md`）

## S5. お小遣い（US8.1、US8.2、US6.1）

```
+--------------------------------------+
| [<] 2027年1月のお小遣い [>]           |  h1
| 確定していません                      |
+--------------------------------------+
| 太郎                       1,200円    |  h2
|   皿洗い     100円 x 8回 =   800円    |
|   風呂掃除   150円 x 4回 =   600円    |
|   減額  -200円（片付けをしなかった）  |
|                 [消す] (管理者のみ)   |
+--------------------------------------+
| 花子                         900円    |  h2
|   ...                                 |
+--------------------------------------+
| 次郎                           0円    |  h2
|   今月の記録はまだありません          |
+--------------------------------------+
| [加算・減額を入れる]  (管理者のみ)     |
| [この月を確定する]    (管理者のみ)     |
+--------------------------------------+
```

- 子供ごとに、種類ごとの「単価 × 回数」と、加算・減額を内訳で表示する（FR8.1）
- 単価が月の途中で変わったときは、単価ごとに行を分けて表示する（例: 「皿洗い 100円 x 3回」「皿洗い 120円 x 1回」）（FR2.2）
- 合計がマイナスのときは「-200円」と記号付きで表示し、0 円にそろえない（FR8.3）
- 「この月を確定する」は確認の小窓を出し、確定すると見出しの下が「確定済み」になり、ボタンが「確定を取り消す」に変わる（FR6.5）
- 加算・減額の行には、管理者にだけ「消す」を出す。押すと確認の小窓（「太郎の減額 -200円（片付けをしなかった）を消しますか？」）を出し、消すと合計に反映する。金額や理由を直したいときは、消してから入れ直す（`stories.md` の AC8.2.5、`requirements.md` の NFR6）
- 確定している月は、加算・減額の「入れる」「消す」のボタンを出さない（FR6.5）
- 子供が見るときは、自分の行を太字と緑の枠で目立たせる（Q5）

## S6. 加算・減額（管理者のみ、US8.2）

```
+--------------------------------------+
| 加算・減額                            |  h1
| 子供                                  |
| [太郎 v]                              |
| 種類                                  |
| ( ) 加算  (x) 減額                    |
| 金額（円）                            |
| [ 200 ]                               |
| 理由                                  |
| [ 片付けをしなかった              ]   |
| [保存]  [やめる]                      |
+--------------------------------------+
```

- 金額は 1 円以上の整数、理由は必ず入れる。誤りは欄のすぐ下に「金額は 1 円以上の整数で入力してください」「理由を入力してください」と出し、入力した内容は残す（FR8.2）
- 1 月にも間に合いそうにない場合は、この画面だけを最初の版から外す（`stories.md` の US8.2）

## S7. 家族の設定（管理者のみ、US1.1、US1.2）

```
+--------------------------------------+
| 家族の設定                            |  h1
+--------------------------------------+
| 家族のメンバー                        |  h2
|   お母さん（管理者）                  |
|   太郎 / 花子 / 次郎                  |
|   [招待のリンクを作る]                |
+--------------------------------------+
| お知らせ先のグループ                  |  h2
|   登録されています: 家族のグループ    |
|   (未登録のときは:                    |
|    登録されていません。               |
|    公式アカウントを家族のグループに   |
```

- お知らせ先は、管理者が公式アカウントを家族のグループに招待し、そのグループで登録する（FR1.5）。登録のしかた（グループで送る言葉など）は設計の段階で決める
- 別のグループで登録し直すと、お知らせ先は新しいグループに置き換わる（FR1.5）

## T1. 1 対 1 のトーク: リッチメニューで記録する（子供、US5.1）

```
(公式アカウントとの 1 対 1 のトーク)

  公式: どれをやりましたか？
        [ 1/5 皿洗い ]  [ 1/5 風呂掃除 ]      <- 返事のボタン
                                   太郎: やった
  公式: 皿洗いを記録しました（16:42）
------------------------------------------------
| [ やった ]          | [ カレンダーを開く ]    |  <- リッチメニュー
------------------------------------------------
```

| 場合 | 公式アカウントの返事 |
|------|---------------------|
| 今日の「未」の担当がある | 担当ごとのボタン（日付とお手伝いの名前） |
| 担当を選んだ | 「皿洗いを記録しました（16:42）」。本人にだけ届き、グループには届かない（FR5.2） |
| 今日記録できる担当がない | 「今日記録できる担当はありません」（FR5.4） |
| 今月が確定している | 「この月は確定済みです」。記録しない（FR5.4） |
| ボタンが出たあとに確定された・状態が変わった | 「この月は確定済みです」など、押した時点の理由を返事し、記録しない |

- 「済」「×」の担当はボタンに出さない（FR5.3）
- 同じボタンを短い間に 2 回押しても、記録は 1 件だけ（FR5.3）

## T2. グループのトーク: リマインド、代わりにやる、月末のまとめ（US9.1、US7.1）

```
(家族のグループのトーク)

  公式: 今日の担当です（1/8 16:00）
        太郎: なし / 花子: 皿洗い / 次郎: 洗濯たたみ

  花子: 家事交代
  公式: 代わってほしい担当を選んでください
        [ 1/8 皿洗い ]  [ 1/12 皿洗い ]
  公式: 花子が 1月8日 の皿洗いを代わってくれる人を探しています
        [ 引き受ける ]  [ 申し出をやめる ]
  公式: 太郎が 1月8日 の皿洗いを引き受けました

  公式: 1月のお小遣い（1/31 21:00）
        太郎 1,400円 / 花子 900円 / 次郎 0円
        くわしくはアプリで見られます
```

| 場合 | 公式アカウントの返事 |
|------|---------------------|
| 「家事交代」で、申し出られる担当がある | 確定していない月の、今日以降の「未」の担当をボタンで出す（FR7.1） |
| 今月が確定していて、申し出られる担当がない | 「この月は確定済みです」（FR7.1） |
| 申し出られる担当がない | 「申し出られる担当はありません」（FR7.1） |
| 同じ担当にすでに申し出がある | 「この担当はもう申し出ています」（FR7.5） |
| 引き受けた | 「太郎が 1月8日 の皿洗いを引き受けました」（FR7.3） |
| すでにほかの子供が引き受けた | 「この申し出はもう引き受けられています」（FR7.3） |
| 申し出た本人や管理者が「引き受ける」を押した | 「この申し出には応えられません」（FR7.3） |
| 申し出をやめた、または申し出がなくなった | 「この申し出はもうありません」（FR7.4・FR7.5） |
| お知らせ先として登録されていないグループ | 「このグループは家族のお知らせ先として登録されていません」（FR1.5） |
| 申し出た本人以外が、担当を選ぶボタンや「申し出をやめる」を押した | 「この操作は申し出た人だけができます」。何も変えない |

- 毎日 16 時のリマインドは、担当がある日に 1 回だけ送る。確定している月は送らない（FR9.1）
- 月末 21 時のまとめは、確定していてもいなくても 1 か月に 1 回送る（FR9.2、FR6.5）
- まとめには、家族のすべての子供を載せる。記録がない子供は「0円」、合計がマイナスの子供は「-200円」のように、アプリと同じ書き方で載せる（`stories.md` の AC9.1.5 の例に合わせる）
- 管理者がグループで「家事交代」と送ったときは「代わってもらう申し出は子供だけができます」、子供が 1 対 1 のトークで「家事交代」と送ったときは「代わってほしいときは、家族のグループで『家事交代』と送ってください」と返事する（U8 の機能設計 Q2。`stories.md` の「あとの段階で決めること」）
