## Way of Working

（おすすめの初期値・未確定）

- 私たちは **trunk-based development**（`main` に短い期間で取り込み続けるやり方）で進めます。ブランチの元は `main`、取り込み先も `main` です。
- Construction で AI-DLC が作る作業用ブランチ（Bolt ごと）は、Bolt の名前を付けた 1 つのコミットとして `main` に **squash-merge** します。
- 依頼して作るコミットは、今いるブランチにそのまま作ります。別のブランチを作るのは、頼んだときだけにします。
- 環境を分ける場合も、長く残るリリース用ブランチは作らず、タグや環境ごとの設定で区別します。
- 聞き取りで確かめること: 1 人で作るので、プルリクエストを作ってから取り込むか、`main` に直接取り込むか。リポジトリを GitHub などに置くか（現在はコミットがまだ 1 つもありません）。

## Walking Skeleton

（おすすめの初期値・未確定）

- 範囲 `mvp` の設定は `skeleton: on` なので、最初に「端から端まで通る、いちばん小さい動く形」を作ります。
- 最初の Unit は、LINE のログイン → LIFF の画面 → Lambda 上の API → データの保存 → 公式アカウントからの返事までが、最小限の形でつながることを確かめるものにします。
- その動作は、この作業のために人が決めて記録した確認用のコマンドで確かめ、人が確認して承認してから、残りの Unit に進みます。
- 聞き取りで確かめること: 最初に細い通り道を作ってから機能を作るか（使う流れの順に作る、という範囲の定義 Q8 との関係も含めて）。

## Testing Posture

（おすすめの初期値・未確定）

- **Methodology**: test-after
- **Methodology evidence**: チームとして決めたテストの進め方はまだありません。`org.md` の初期値（決まっていなければ test-after）と、範囲 `mvp` の初期値をそのまま使っています。新しいプロジェクトなので、既存のテストやテストの道具は見つかっていません。聞き取りで決め直します。
- **Ordering**: テストできる層ごとに、先にその層を作り、そのあとでその層のテストを書いて実行します。
- 範囲 `mvp` の下限として、行カバレッジ 80% 以上と、取り込み前の CI でのテスト実行を求めます。
- 選んだテストの量（Test Strategy）はどの範囲でも適用し、上の下限はそれに追加するもので、減らすものではありません。
- Build and Test では、決めたカバレッジの下限と品質の目標を確かめます。通すために下限を下げることはしません。
- 聞き取りで確かめること: テストの進め方（test-after のままか、TDD などにするか）。テストの道具（例: Vitest や Jest）。CI を無料枠の中で動かせるか（費用 0 円の制約 C-F1）。

## Deployment

（おすすめの初期値・未確定）

- `main` に取り込んだら、ステージング環境に自動で配備します。
- 本番環境への配備は、別に手動で承認してから行います（`org.md` では技術の責任者と製品の責任者の承認としていますが、作り手が 1 人なので、本人の承認になります）。
- 聞き取りで確かめること: 費用 0 円（C-F1）のまま、ステージングと本番の 2 つの環境を持てるか、持つ必要があるか。配備の道具（例: AWS CDK、SAM、Serverless Framework）と、配備をどこから動かすか（手元のパソコン、GitHub Actions など）。元に戻す方法（Lambda の前の版に戻すなど）。

## Code Style

（おすすめの初期値・未確定）

- コードの書き方は、プロジェクトに置く設定ファイルに従います。TypeScript と React では、整形に Prettier、静的な検査に ESLint を使い、設定はリポジトリの一番上に置きます。
- 検査は取り込み前の CI で実行し、失敗したら取り込みません。
- 名前の付け方は言語の慣習に従います（TypeScript では camelCase など）。プロジェクト全体の特別な決まりは、決めたときだけ追加します。
- AI-DLC からの書き方の提案は、検査ツールの設定を先に読み、その設定で扱っていないことだけにします。
- 聞き取りで確かめること: Prettier と ESLint をそのまま使うか、ほかに決めておきたい書き方（例: default export を使わない、エラーの返し方）があるか。
