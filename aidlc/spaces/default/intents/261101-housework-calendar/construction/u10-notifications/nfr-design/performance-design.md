# 性能設計 — U10 お知らせ

## 遅延の配分

NFR7.101〜NFR7.103、NFR11.101を満たすため、定時起動→家族の列挙→家族単位の永続キュー→通知処理に分ける。正常時の最初の試行までの60秒は、起動30秒、列挙と受け渡し10秒、家族ごとの読み取りと送信20秒を検証用の予算とする。20回中19回を確認し、達成できなければ配備前に設計を再評価する。

- 通知処理1回の実行上限は30秒。読み取り1要求は2秒、外部配信は5秒で打ち切る。内部の自動再試行でこの上限を隠して超えない。
- 家族の処理は最大2並行、名前などの補完読み取りは家族内で最大10並行。1回の実行で複数回の配信をせず、待ち時間は永続キューへ返す。
- 送信開始直前の残り時間が5秒未満なら新しい外部通信を始めない。15分後未満という開始条件に加え、通信の上限も期限内へ収める。
- 担当と金額にプロセスをまたぐキャッシュを設けない。1回の配信準備で同じ情報を重複して取得しない。再試行は保存した本文を使う。
- 画面用・LINE用の対話処理とは起動経路と並行数を分離し、通知を同期呼出ししない。
- 日本時間の実在日付と月末判定を共有の日付部品で行う。起動時と送信直前の時計を差し替え可能にし、UTC日付へ読み替えない。

## 検証

1家族4人・当日100件・月3100件と10家族で、遅延・読み取り回数・最大並行数を記録する。先読みや常駐待機は行わない。外部応答を遅らせた試験と、ステージングの冷たい起動を分けて確認する。
