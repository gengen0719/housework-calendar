# 信頼性の要件 — U10 お知らせ

| ID | 要件 | 確かめ方 |
|---|---|---|
| NFR2.101 | 稼働率の新しい数値目標は置かない。通知送信・裏側のエラー・予定起動の欠落を、発生または予定時刻から15分以内に作り手のメール受信まで確認する。 | ステージングで送信失敗、起動欠落、APIとLINE入口の失敗をそれぞれ作る。 |
| NFR2.102 | 保存・読込ができないときは外部送信しない。複数家族のうち1家族が失敗しても他の家族は処理を継続する。部分的な金額や担当一覧は送らない。 | 依存先ごとの失敗とページ途中の失敗を差し込む。 |
| NFR2.103 | 二重起動・並行実行・送信後の保存失敗・通信タイムアウトで、同じ論理通知を別キーで送らない。受理済みの照合は同じ要求だと検証できる場合に限る。 | 受理直後の中断、所有期限、同時実行を再現する。 |
| NFR2.104 | 自動再送は予定時刻から15分未満。予定時刻前と15分後ちょうど以降の新規送信は0回。回数上限を超える自動再送もしない。 | 時計固定と試行回数の検査。 |
| NFR2.105 | 恒久的な認証・入力・宛先エラーを繰り返さない。配信先が変わった後に別宛先へやり直さない。 | エラー分類と宛先変更の試験。 |
| NFR2.106 | バックアップ復旧や記録の削除を古い通知の再送につなげない。復旧時も時刻検証を最初と送信直前に適用する。 | 古い記録・記録なし・期限切れイベントを再現する。 |
| NFR8.101 | BDDで振る舞いの筋書きを実装より先に書き、部品ごと5〜8件と主要境界の結合テストを用意する。全体の行カバレッジ80%以上を維持する。 | 単位のテスト、既存全体テストとCI。 |
| NFR10.101 | ステージングと本番の通知先・秘密・起動を分離する。本番を対象としたテスト配信を自動テストから行わない。 | 構成検査とステージングのみの配信手順。 |

メール受信の確認・実際の外部配信の確認が終わるまでは、15分以内の目標や本番配信が検証済みとはしない。配信サービスの受理確認だけで利用者の端末への到達を保証しない。
