# 容量と費用の要件 — U10 お知らせ

| ID | 要件 | 確かめ方 |
|---|---|---|
| NFR3.101 | 既存のサーバー常駐なしの構成に通知を追加する。待機のため常時動く処理を持たない。 | 配備構成と再試行方式の確認。 |
| NFR3.102 | 家族と担当の列挙はページの終わりまで処理し、1ページ目だけで終了しない。同時処理数と1回の取得件数に上限を設ける。 | 複数ページ・0件・1件・上限超過の試験。 |
| NFR3.103 | MVPの検証基準として1家族4人、当日担当100件、月の担当3100件で処理する。複数家族の分離試験は10家族で行う。これは負荷試験の基準であり、利用者に課す新しい制限ではない。上限を超えた本文は黙って省略せず失敗として知らせる。 | 大きな前提データと家族単位の失敗隔離。 |
| NFR1.101 | 家族への自発通知は毎日最大1通と月末最大1通だけ。31日ある月は最大32通。配信サービス上の課金通数は家族の人数を含めて別に確認する。 | 1か月の送信履歴と通数の算出を検査。 |
| NFR1.102 | U10インフラ設計Q2の利用者回答「B 100円」に従い、ステージングと本番を合わせて月100円以内を目標とする。新しい構成と監視・メール・再試行・データ保持の費用を配備前に見積もる。無料枠の適用条件を未確認のまま無料と断言せず、予算通知を請求の強制停止とみなさない。 | 対象リージョンと公式の料金・無料枠の確認、合算見積もり、予算通知、実際の月額費用の確認。 |

家族数を無制限に増やした場合の性能や無料運用は保証しない。基準を超える見込みがあるときは、構成と費用を再評価する。利用人数の確定値は実配備時の見積もりへ入力する。
