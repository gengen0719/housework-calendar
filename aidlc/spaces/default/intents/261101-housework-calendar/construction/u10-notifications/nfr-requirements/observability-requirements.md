# 監視の要件 — U10 お知らせ

| ID | 要件 | 確かめ方 |
|---|---|---|
| NFR2.107 | 正常送信、正常省略、重複抑止、再試行、期限切れ、恒久失敗を区別して記録する。予定起動の欠落は実行自身のログに頼らず検知する。 | 各分岐と起動を止める試験。 |
| NFR2.108 | 初回失敗の時点で監視へ渡し、15分の再送期限が尽きるまで障害通知を待たない。監視とメール配信の遅延予算を後続設計で割り当てる。 | 初回失敗からメール受信までの実測。 |
| NFR2.109 | API・LINE・お知らせの全入口でエラーを検知し、作り手へメールで知らせる。通知先の購読未確認を配備完了とみなさない。 | 3入口の異常試験と購読・受信確認。 |
| NFR4.105 | 許可した運用項目だけをログとメールへ出す。エラーの生の本文やリクエスト全体を出さない。ログ内の異常データは上限を設け、全件の総数は集計で残す。 | 名前・金額・秘密を含む異常入力で検査。 |
| NFR6.102 | 該当日・通知種類・運用用識別子から失敗の分類と次の対応を追える。確認手順に「送信済みを再送しない」「秘密をログへ貼らない」を含める。 | 手順書を使った障害調査の実演。 |

SLIは予定起動率、初回試行の遅延、受理成功数、失敗数、重複抑止数、期限切れ数、メール通知までの遅延。通知対象のない正常省略は送信失敗率の分母に含めず、件数を別に表示する。稼働率の数値SLOは新設しない。通知本文を分散追跡の属性へ入れない。
