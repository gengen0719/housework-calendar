# 量と費用の設計（Scalability Design）— U8 代わりにやる

U8（`u8-swap`）の量と費用の要件（`nfr-requirements/scalability-requirements.md` の NFR1.32〜NFR1.34、NFR3.14〜NFR3.16）を、どう作るかを書きます。U1〜U7 の設計（オンデマンドの DynamoDB、`line`・`api` の同時実行の上限、家族のキー）はそのまま使います。U8 は **push を使わず、新しい課金対象を足しません**。費用 0 円（NFR1）をこの 2 つで守ります。

## 量の前提

家族 4 人（子供 3 人）で、申し出は 1 か月に多くて数回です。1 回の申し出につき LINE の操作は 3〜4 回（「家事交代」、担当を選ぶ、引き受ける、まれに取り下げる）で、`line` の Lambda の無料枠（月 100 万回）のごく一部です。保存するのは、申し出られた担当 1 つにつき `Calendar` の項目 1 つです。月の確定のときだけ、確定の時点で「未」だった担当の数（多くて数百）の条件つき書き込みが `api` から出ます。

## LINE の送信（NFR1.32、NFR3.16）

| 設計 | 内容 |
|------|------|
| 返事の経路 | すべて reply トークンで、イベントが届いたグループ（1 対 1 の案内は 1 対 1）に送る。`push`・`multicast`・`broadcast`・`narrowcast` は使わない |
| 呼び出し | 1 イベントにつき reply の呼び出し 0 回か 1 回。1 回の返事は 3 通以内（見出し・carousel・案内。LINE の 1 回 5 通の上限に収まる） |
| 無料枠 | U8 の操作は月 200 通の数に 1 通も足さない（返事は数に入らない前提。返事ではないお知らせの月 128 通の枠は U10 の分） |
| 「探しています」の知らせ | 担当を選んだ人への返事として出す（push ではない）。ほかの子供に個別に知らせる通知は作らない |
| carousel | 1 バブル 1 担当で **10 件まで**（LINE の上限の仮定 12 に収まる）。11 件以上のときだけ案内を 1 通添える（BR9.6） |
| 一覧の読み取り | 担当の数で増えない（今月と来月の月の Query 各 1 回。`performance-design.md`） |
| `line` の同時実行 | U1 の値（NFR1.6、NFR3.6）のまま。U8 で変えない |

- 単体テストで、U8 のコードが LINE の API を `POST /v2/bot/message/reply` だけ、1 イベントにつき 0 回か 1 回呼ぶこと、`push`・`multicast`・`broadcast` を含む呼び出しが 0 件であることを確かめます
- carousel は候補 1 件・10 件・11 件・124 件で、バブルが 10 以内、案内の通は 11 件以上のときだけ付くことを確かめます
- ステージングの測定（NFR7.48）の前後で、公式アカウントの月の送信数が増えないことを見ます（返事が数に入らないことの確認も兼ねる）

## テーブルの形と項目（NFR1.33、NFR3.14）

| 項目 | 設計 |
|------|------|
| 新しいテーブル・索引・TTL | **なし**。`DataStack` は変えない |
| 申し出の置き場所 | `Calendar` の `familyId` ＋ `sk = SWAP#<dutyId>`。担当 1 つにつき 1 項目、1 つの担当に出せる申し出は 1 つ（FR7.5） |
| 数と大きさ | 申し出られた担当の数以下。1 家族・1 か月に多くて 300 件、1 項目は数百バイト、1 年で 1 MB に満たない |
| 残し方 | 引き受け・取り下げ・自動でなくなったあとも項目を残す（TTL なし）。件数が小さいので費用にも読み取りにも影響しない |
| 月の Query との関係 | `SWAP#` は `M#` と重ならないので、U5 の月の Query（`begins_with M#<month>#`）と種類の使用の確かめ（`begins_with M#`）には入らない |
| 読み取り | 申し出は**キーを指定した `GetItem`（強い整合性）だけ**。家族のパーティション全体を読む `Query`（`begins_with` のないもの）は書かない。`Scan`・`BatchGetItem`・`BatchWriteItem` も使わない |
| 追加の構成 | Lambda 関数、ログのグループ、CloudWatch のカスタム指標（メトリクスフィルター）、アラームを足さない。権限と環境変数も足さない（`security-design.md`）。指標とアラームは U10 |

- 単体テストで、U8 のコードの `Query` がすべて `begins_with` を持つか、月の状態・種類の既存の `Query` であること、`Scan`・`BatchGetItem`・`BatchWriteItem` が 0 回であること、月の Query の結果に `SWAP#` の項目が混ざらないことを確かめます。担当 1 件・124 件・300 件でも、読み取りの回数が `performance-design.md` の上限に収まることも確かめます
- CDK のテストで、U8 の前後にテーブル・索引・Lambda・ログのグループ・指標・アラームの数が変わらないことを確かめます（`logical-components.md`）

## フックの書き込みと並行数（NFR1.34、NFR3.15）

- フックは 1 回につき申し出の項目への条件つき `UpdateItem` 1 回です。月の確定のときは、確定の時点で「未」だった担当の数（多くて 300 件）だけ動きます。条件に合わず断られる書き込みも 1 書き込み分の容量を使います
- 費用の見積もり（未確認）: 300 件の書き込みはオンデマンドの書き込み 300 単位で、1 回の確定あたり 1 円に遠く及びません。確定は 1 か月に数回なので、U8 による DynamoDB の追加の費用は月に 1 円に満たず、AWS の請求額は 0 円のままです。料金の単価は、コード生成で公式の料金表を確かめて数を残します
- 並行数は `DUTY_HOOK_CONCURRENCY`（初期値 4、範囲 2〜5）の 1 つの定数にまとめます（`performance-design.md` の ADR-U8-01）。`Calendar` の項目は同じ家族の同じパーティションキーに集まるので、毎秒の書き込みを 1 つのパーティションの目安（毎秒 1,000 件）に収めます。5 にするのは `WriteThrottleEvents` が 0 のままのときだけで、スロットルが出たら下げます
- 単体テストで、300 件のイベントを渡したとき同時に動く関数が 4 件を超えないこと、すべてのイベントが 1 回ずつ呼ばれること、関数が投げても残りが続くこと、書き込みが「渡されたイベントの数以内」で余計な読み取り・書き込みがないことを確かめます

## 状態を持たない作り

- `line` と `api` の Lambda は状態を持ちません。申し出の状態はすべて `Calendar` にあり、フックの登録の記録（`registerSwapHooks` を呼んだか）は実行環境ごとのメモリの上のフラグだけです（`reliability-design.md`）。実行環境が増えても、それぞれが 1 回だけ登録するので二重にはなりません
- 担当ごと・月ごとに項目が分かれているので、複数の実行環境が同時に動いても、取引の条件で取り違えません

## 見守る費用

毎月の請求を作り手が見ます（NFR1.5）。U5 の最初の請求の確認（`Calendar` の行）に U8 の増分を含めて見ます。測定（NFR7.46）の前後で `Calendar` の書き込みの数が想定の範囲であることを確かめます。

## Assumptions & Open Questions

- [assumption] LINE の reply が公式アカウントの無料のメッセージ数に数えられない、という前提（U6 の NFR1.24 と同じ）は、公式の説明をこの段階では確かめられていません。ステージングの送信数の前後の比較で確かめます。数えられるとわかった場合は、NFR1 の枠の見積もりを見直します
- [assumption] DynamoDB のオンデマンドの単価と「条件で断られる書き込みも 1 書き込み分を使う」は、公式の説明をこの段階では確かめられていません。見積もりは桁として 1 円に満たないので、結論は変わらない見込みです。コード生成で公式の料金表と照らします
- [assumption] 申し出の項目を消さずに残す件数は、1 年で数千件以下と見ています。増え続けても読み取りは `GetItem` だけで、`SWAP#` を一括で読む処理がないので影響しません。長く運用して掃除が必要になったときの手順は運用の段階で決めます（本番のデータは手で書き換えない。NFR6.9）
- [assumption] 並行数 4 は未測定の見積もりです。測定で変えます
- このステージで人に聞くことはありません
