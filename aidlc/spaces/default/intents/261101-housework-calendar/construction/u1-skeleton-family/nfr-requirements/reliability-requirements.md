# 止まらないことの要件（Reliability）— U1 最初の形と家族を作る

U1（`u1-skeleton-family`）の、止まらないこと、失敗したときの扱い、データの守り方の要件です。稼働率の数値目標は置きません（NFR2）。

## 要件

| ID | 要件 | 確かめ方 |
|----|------|---------|
| NFR2.1 | 裏側の思いがけない失敗は、必ずログに残す（何の操作で、どの利用者か、どんな失敗か。秘密の情報は書かない）。作り手への知らせは U10 で入れる | 失敗したときにログが出る単体テスト |
| NFR2.2 | LINE のイベントの処理で思いがけない失敗が起きたら、「処理中」の記録を消して 500 を返し、LINE に送り直してもらう [Q1]。Lambda が止まって記録を消せなかったときは、2 分たてばやり直す [Q7] | 失敗させたあとの送り直しで、正しく処理されること |
| NFR2.3 | 家族の作成と利用者の更新は、両方できるか、両方できないか（BR1.7）。途中で止まっても、家族だけできて管理者がいない状態を残さない | 途中で失敗させて、どちらも残らないこと |
| NFR2.4 | LINE に問い合わせられなかったとき（友だちかどうかの確かめ）は、利用者を断らず、「表示できませんでした。もう一度お試しください」を出して読み込み直せるようにする（BR1.11） | LINE への呼び出しを失敗させて、その表示が出ること |
| NFR6.1 | 本番のデータを手で書き換えない。U1 のデータは、アプリの操作（友だち登録、家族を作る）と、CDK で作る構成でだけ変わる（`project.md` の Forbidden） | — |
| NFR6.2 | DynamoDB のテーブルは、CDK でスタックを消してもテーブルが消えない設定にする（本番）。ポイントインタイムリカバリは費用がかかるので使わない | CDK の設定で確かめる |
| NFR10.1 | ステージングと本番は、別の AWS のスタックと、別の LINE 公式アカウントとチャネルを使う。ステージングの設定で本番のデータやチャネルに届かない | 環境ごとのパラメータで確かめる |
| NFR10.2 | `main` に取り込むとステージングだけに反映し、本番は作り手が手で反映する | CI の設定で確かめる |
| NFR11.1 | 時刻は UTC で持ち、日付の区切りが必要なときは日本時間で扱う。U1 で持つ時刻（友だち登録の時刻など）は UTC | 単体テスト |
