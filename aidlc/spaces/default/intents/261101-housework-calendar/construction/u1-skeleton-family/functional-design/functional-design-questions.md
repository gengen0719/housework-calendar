# 機能設計 — U1 最初の形と家族を作る — 質問

U1（`u1-skeleton-family`）の中身を決めます。U1 は最初の形（walking skeleton）で、次の流れを本物の機能でつなぎます。

- 友だち登録すると、公式アカウントが返事をする
- LINE ログインで画面を開き、「家族を作る」で管理者として家族ができる

受け持つ受け入れ条件は、AC1.1.1〜AC1.1.5、AC1.1.10〜AC1.1.12 です（`unit-of-work-story-map.md`）。招待の AC1.1.6〜AC1.1.9 と AC1.1.13 は U2 で作ります。

すでに決まっていること（もう一度は聞きません）:

- 友だち登録の記録は重複させない。ブロックしてから登録し直しても同じ人として扱う（AC1.1.2）
- すでに家族に入っている人は、2 つ目の家族を作れない（AC1.1.5）
- 画面からのすべての要求で、認証と家族のメンバーであることを確かめる（AC1.1.11、AC1.1.12、契約の C1・C2・C6）
- セッションの期限と保存場所、受け取ったイベント ID を残す期間は、技術の決めごとなので、このあとの NFR の段階で決める

ここでは、要件にまだ書かれていない細かい場合の扱いを決めます。

## Q2. [プロダクト] 友だち登録していない人がアプリを開いたとき

`stories.md` の「あとの段階で決めること」に残っていた点です。公式アカウントを友だち登録していない人が、LINE の中やパソコンのブラウザからアプリを開いたときの扱いです。

A. 画面を開いたときに利用者として記録し、そのまま「家族を作る」「招待を待つ」を出す。友だち登録していなければ、画面で友だち登録を案内する（お知らせやリッチメニューを使うには友だち登録が必要なため）
B. 友だち登録していない人には、友だち登録の案内だけを出し、登録するまで「家族を作る」「招待を待つ」を出さない
