# 信頼性の要件（Reliability）— U2 招待

U2（`u2-invitation`）の信頼性の要件です。U1 の要件（NFR2.1〜NFR2.4、NFR6.1、NFR6.2、NFR10.1、NFR10.2、NFR11.1）をそのまま使います。

## 要件

| ID | 要件 | 確かめ方 |
|----|------|---------|
| NFR2.10 | 招待の作り直しは、前の招待を replaced にすること・新しい招待を作ること・家族のいまの招待の ID を変えることを 1 回のトランザクションで行う。どれかができなければ、どれも残さない（BR3.4） | 途中で失敗させて、使える招待が 2 つにも 0 つにもならないこと（前の招待が使えるまま残ること） |
| NFR2.11 | 参加は、利用者の家族・役割・家族に入った時刻の書き込みを、「利用者がまだ家族に入っていない」と「招待がいまの招待で期限内」の両方を条件にした 1 回のトランザクションで行う（BR3.8） | 同時に 2 つの招待で参加させて、1 つだけ成功すること。確かめたあとに作り直させて、参加できないこと |
| NFR2.12 | 作り直しのトランザクションが同時の作り直しで条件に合わないときは、1 回だけ読み直してやり直す。それでも合わなければ 500 `INTERNAL` を返し、画面は「表示できませんでした。もう一度お試しください」を出す（BR3.4） | 条件に合わない状態を作って、その表示が出ること |
| NFR2.13 | 招待の期限は UTC で持ち、画面には日本時間で「（月/日 時:分）まで使えます」と出す。期限の判断は裏側の時刻で行い、画面の時刻は使わない | 単体テストで、期限のちょうどの時刻に使えないこと |
| NFR6.3 | 招待と参加のデータは、アプリの操作でだけ変わる。本番のデータを手で書き換えない（`project.md` の Forbidden）。参加した子供を家族から外す操作は最初の版にはない | — |
