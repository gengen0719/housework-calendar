# インフラ設計 — U2 招待 — 質問

U2（`u2-invitation`）のインフラは、U1 の構成（同じ AWS アカウント、`ap-northeast-1`、スタックは Data と App、GitHub Actions で `main` からステージングに自動で反映、本番は手で反映、元に戻すのは `git revert`）に足すだけです。足すものは NFR 設計で決めました（Invitations テーブル、Users の `familyId-index`、画面用の Lambda の権限、使えない印の数のメトリクスフィルタ）。

ここで聞くのは、反映したあとの確かめ方の 1 つだけです。

## Q1. [インフラ] 反映したあとの確かめ（`scripts/smoke-check.sh`）

いまは反映したあとに、画面が出ること、セッションがなければ `/v1/me` が 401 になること、署名のない Webhook が 401 になること、関数 URL を直接呼ぶと 403 になることを確かめています。U2 の操作の分をどこまで足しますか。

A. セッションなしで U2 の 5 つの操作（メンバーの一覧、いまの招待、招待を作る、招待を開く、参加する）を呼び、どれも 401 になることを足す。ログイン済みの確かめ（招待を作って参加する）は、作り手がステージングで手で行う
B. A に加えて、反映のたびに、テスト用の LINE アカウントのセッションで招待を作って開くところまで自動で確かめる（テスト用のアカウントと、その ID トークンを取る仕組みを用意する必要がある）
X. Other (please specify)

[Answer]: A
