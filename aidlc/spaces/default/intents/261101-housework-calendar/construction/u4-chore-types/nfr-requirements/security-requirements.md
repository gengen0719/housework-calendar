# 安全の要件（Security）— U4 お手伝いの種類

U4（`u4-chore-types`）の安全の要件です。U1〜U3 の要件（NFR4.1〜NFR4.33、NFR5.1〜NFR5.9）は、そのまま使います。ここでは U4 で足すものを、U3 の番号の続きで書きます。U4 は画面用 API の操作を足すだけで、新しい秘密の情報も LINE の操作もないため、NFR の段階では人に聞くことはありませんでした（決まっていないことがない）。

## 認可

| ID | 要件 | 確かめ方 |
|----|------|---------|
| NFR4.34 | `POST`・`PUT`・`PATCH`・`DELETE /v1/chore-types…` は C6 の requireAdmin で管理者かを確かめ、子供は 403 `ADMIN_ONLY`（BR5.1、AC2.1.3）。管理者の確かめは、種類があるかの確かめ（404）より先に行う | 子供のセッションで、ある種類にもない種類にも 403 になり、何も変わらないこと |
| NFR4.35 | `GET /v1/chore-types` は家族のメンバーだけ（U1 の NFR4.5）。返すのはその家族の種類だけ（BR5.11） | ほかの家族の種類が含まれないこと |
| NFR4.36 | 種類の ID を指定する操作と C7 の窓口は、種類の familyId が ctx.familyId と違えば、種類がないときと同じ 404 `NOT_FOUND` を返す（ほかの家族の種類があることを知らせない。BR5.10、U1 の NFR4.6） | ほかの家族の種類の ID で、ない ID と同じ応答になること |

## 入力の確かめ

| ID | 要件 | 確かめ方 |
|----|------|---------|
| NFR4.37 | 本文は型と長さを確かめてから使う。名前は Unicode の NFC に正規化し、前後の空白（全角を含む）を除いて 1〜20 コードポイントで、改行を含む制御文字を断る（BR5.2）。名前の重なりは、NFC に正規化した名前で比べる（全角と半角は別の名前のまま。見た目が同じで中身が違う文字の組み合わせは同じ名前になる）。単価は JSON の整数で 0 以上、安全な整数の範囲まで（文字列は 422。BR5.5）。説明は NFC に正規化して 100 コードポイントまで。改行は許し、ほかの制御文字は断る（BR5.6）（レビュー R-03）。知らない項目は無視し、`familyId` や `choreTypeId`、`active`（PUT のとき）を本文で受け取っても使わない | 長すぎる名前、制御文字、`"100"`、`-1`、`1.5`、2^53 の単価、101 文字の説明が 422 で断られること。本文の familyId が無視されること |
| NFR4.40 | `PATCH /v1/chore-types/{choreTypeId}` の本文は `active` だけを使い、JSON の `true`・`false` だけを受ける。文字列（`"false"`）、数（`0`）、欠けている、本文がないは 422 `INVALID_REQUEST`。`active` 以外の項目は無視する。パスの `choreTypeId` は形（UUID）を先に確かめ、合わなければ DynamoDB を読まずに 404 `NOT_FOUND`（U2 の NFR4.16 と同じ考え。レビュー R-01） | `"false"`・`0`・本文なしの PATCH が 422、形の違う ID が 404 になり、何も変わらないこと |
| NFR4.41 | 確かめの順番は、セッション → 家族のメンバー → 管理者 → `Idempotency-Key` の形（POST）→ 種類の ID の形と種類の 404（家族の範囲）→ 本文の 422 → 名前の重なりの 409。ほかの家族の種類の ID には、本文が正しくても誤っていても 404 を返す（ほかの家族の種類があることを 422・409 で漏らさない）。同じ印で本文や操作が違う送り直しは、U2 の NFR4.22 と同じく 422 `IDEMPOTENCY_KEY_REUSED`（レビュー R-02） | ほかの家族の種類の ID に誤った本文で送っても 404 になること。同じ印で別の本文を送って 422 になること |
| NFR4.38 | 画面では、名前と説明を HTML として差し込まない（U1 の NFR4.12） | 画面のテストで、名前の中のタグが文字として出ること |
| NFR4.39 | 登録は `Idempotency-Key`（UUID の形）を必須にし、U2 の NFR4.22 と同じく、利用者・印・操作の組で 1 回として扱う（BR5.12） | 同じ印で 2 回送っても種類が 1 つであること |

## 脅威と備え

| 脅威 | 備え | 扱い |
|------|------|------|
| 子供が単価を変えてお小遣いを増やす | NFR4.34 | 備える |
| ほかの家族の種類を見る・変える・消す | NFR4.35、NFR4.36 | 備える |
| 名前や説明に悪いスクリプトを入れる | NFR4.37、NFR4.38 | 備える |
| 大きすぎる単価でお小遣いの計算を壊す | NFR4.37（安全な整数まで）。U9 への引き継ぎ: 子供ごと・月ごとの合計を計算するとき、途中の値が安全な整数を超えるなら計算せずに「金額が大きすぎて計算できません」と出す。U9 の確かめ方: 単価 2^53−1 で記録 2 回の筋書きで、その表示になり、ほかの子供の金額は正しく出ること | 一部を受け入れる（上限なしは機能設計の [Q2] の人の答えなので変えない。単価を変えられるのは管理者だけで、被害は家族の中に限られる。レビュー R-04） |
| CloudFront が PUT・PATCH・DELETE を通さない | U1 の CloudFront の `/v1/*` の振り分けは `AllowedMethods.ALLOW_ALL`（`infrastructure/lib/app-stack.ts`）で、PUT・PATCH・DELETE も通る。秘密のヘッダーの確かめ（U1 の NFR4.13）はメソッドにかかわらず同じに働く。ステージングで 3 つのメソッドを実行して確かめる（レビュー R-07） | 備える |
