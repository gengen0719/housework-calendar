# U11 性能設計

## Read and Interaction Budgets

S5は既存の月読取を使い、管理者の独立した加算減額一覧は別の読取として開始します。登録・削除は応答を待って既存お小遣いと調整一覧を再取得します。重複する同じ読取の多重開始を抑止し、月変更・離脱時には中止と応答番号で旧応答を排除します。保存の成功と表示の失敗は別状態です。

計測用の3秒配分は通信と起動800ms、検証・保存/読取1400ms、再取得と描画800msを目安とし、予算超過を成功と見なしません。実測で各20回中19回を判定します。既存の共有クライアントを再利用し、接続や秘密を要求ごとに再生成しません。表示用の長期キャッシュや別の保存済み合計は設けません。

## Exact Calculation and Recovery

各入力の金額は正のsafe integerで検証します。計算は整数の拡張精度（実装ではBigInt）で単価×回数、小計の和、符号付き調整の和、最終合計まで行い、返す各数値を安全な整数範囲へ検証して変換します。合計の途中だけが上限を超えても、正負が相殺して最終値が範囲内なら成功とします。BigIntそのものはJSONに出しません。

返す小計または最終合計が範囲外なら422 `ALLOWANCE_OUT_OF_RANGE`を返し、0円や丸めた額を返しません。S5は読取エラー表示の横に独立した調整一覧の入口を残します。一覧・削除は集計処理を一切呼ばないため、範囲外の月でも管理者が1件ずつ消して範囲内へ戻せます。通知のC9経路でも範囲外なら送らず、既存の失敗通知経路を使います。

## Query Strategy

家族と月で絞った強整合のQueryを全ページ取得します。キャッシュは使用しません。1000件とページ境界を試験し、一部だけを完全な合計として返しません。APIの処理期限は既存設定内、明示的なDB試行は最大2回とし、残り時間が不足する場合は打ち切ります。無制限に全体をリトライしません。

## Validation

上限額2件、上限額と負額の相殺順序違い、小計自体の範囲外、範囲外からの削除による復帰、1000件、多重クリック、旧月応答の遅延を検証します。実機3秒条件・読み上げ・320px・44×44・4.5:1は手動結果を別に記録します。
