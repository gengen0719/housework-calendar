# U11 画面の構成

## Component Hierarchy

- S5お小遣い画面: 既存の月選択・子供別内訳・合計を使用する。未確定月の管理者に「加算・減額」と各調整行の「消す」を追加する。
- S6加算・減額フォーム: 月表示、子供の選択、加算/減額ラジオ、金額、理由、保存・やめる。
- 削除確認: 対象の子供・符号付き金額・理由、消す・やめる、失敗の表示。

## Props and State

| 部品 | 入力 | 状態 |
|---|---|---|
| S5 | 選択月・所属と権限・既存お小遣い応答 | 読取中/成功/失敗、削除対象 |
| S6 | 対象月・家族内の子供・戻る先 | childUserId、kind、金額文字列、理由、欄別エラー、保存状態、操作キーと送信入力 |
| 確認 | 保存済み行・対象の子供 | 確認中/削除中/失敗 |

## Interaction Flows

S5→S6→成功後同月のS5再取得。「やめる」は保存せず戻る。保存中は二重操作を抑止し、応答不明時は同じ内容の再送を案内する。削除は確認後に実行し、成功時だけ一覧を更新する。確定月・子供には変更操作を表示せず、古い画面からの直接操作もAPIが拒否する。

月変更・画面離脱に伴う旧応答を無視し、保存の成否と再取得の成否を区別する。保存成功後の再取得失敗は、再登録を促す文言にしない。

## Validation and Accessibility

BR12.2・BR12.3に従い金額と理由を欄の下で説明し、入力を残す。見えるラベル、種類のグループ名、キーボード操作、確認のフォーカス移動と復帰、処理結果の読み上げを用意する。押す場所44×44以上、文字のコントラスト4.5:1以上、色に依存しない確定・エラー表示を既存方針から継承する。理由は文字として表示し、入力されたマークアップは実行しない。

## API Integration

登録・削除の境界は`functional-spec.md`、合計・内訳は既存の月別お小遣い読取。家族IDは送信しない。月確定のエラー時は状態を再取得し、その月の変更を止める。
