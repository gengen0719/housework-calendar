# 量と費用の要件（Scalability）— U5 割り当てとカレンダー

U5（`u5-assignment-calendar`）の量と費用の要件です。U1〜U4 の要件（NFR1.1〜NFR1.18、NFR3.1〜NFR3.5）をそのまま使います。

## 量の見込み

家族は 1 つで、1 か月の担当は約 124 件、1 年で約 1500 件です。割り当ての保存は月に数回、カレンダーを開くのは家族 4 人で 1 日に数十回です。

## 要件

| ID | 要件 | 確かめ方 |
|----|------|---------|
| NFR1.19 | U5 で新しく費用のかかる AWS のサービスを足さない。割り当て・担当・月の状態は DynamoDB（オンデマンド）、処理は U1 の画面用の Lambda に足す | CDK の構成で確かめる |
| NFR1.20 | カレンダーは、その家族のその月の担当だけを読む（月をキーに含めた Query。Scan を使わない）。続きがあれば最後まで読む | 単体テストで、読み取りが家族と月の条件つきであること |
| NFR1.22 | `PATCH /v1/duties/{dutyId}`（担当の ID だけで探す）と、C8 `isChoreTypeAssigned`（どの月の割り当てか担当に種類があるか）も、Scan を使わず、強い整合性で読める形にする（索引か、家族の中の Query かは NFR の設計で決める）。1 年分（約 1500 件）でも読み取りの量が月 1 円を超えないこと（レビュー） | 単体テストで、2 つの読み方が家族の条件つきで強い整合性であること |
| NFR1.21 | 1 か月のカレンダーの表示で読む量は、担当の Query と、子供（C6）と種類（C7）の読み取りだけにする（担当 1 件ごとに種類や子供を読まない） | 単体テストで、読み取りの回数が担当の数で増えないこと |
| NFR3.6 | 処理は U1 の画面用の Lambda の同時実行数の上限（5）の中で動く | CDK の構成で確かめる |
