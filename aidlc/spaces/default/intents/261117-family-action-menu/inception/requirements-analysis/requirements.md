# 家族操作メニューの要件

## Intent Analysis

カレンダー上部で大きく表示される管理操作をまとめ、家族名とカレンダーを見やすくする。既存の設定画面・割り当て編集の入口だけを移す、小規模な画面改善である。

## Functional Requirements

すべて Must。Given/When/Then は受け入れ基準を表す。

### FR1 家族名の右端の3点メニュー

出典: [desc]。

- Given カレンダーに家族名が表示されている、When 画面を開く、Then 同じ行の右端に3点メニューの開閉ボタンを表示し、操作項目は初期状態では閉じる。
- Given メニューが閉じている、When ボタンを押す、Then 利用可能な操作を表示する。
- Given メニューが開いている、When ボタンの再操作・外側のクリック・Escapeを行う、Then メニューを閉じ、設定や保存処理を実行しない。

### FR2 家族の設定をメニューへ移動

出典: [desc]、[調査]。

- Given 従来「家族の設定」を利用できる状態、When 3点メニューを開く、Then 「家族の設定」を表示する。従来の大きな独立ボタンは表示しない。
- Given メニューが開いている、When 「家族の設定」を選ぶ、Then メニューを閉じ、既存と同じ設定画面へ進む。
- Given 従来設定操作が許可されない状態、When メニューを開く、Then 従来の権限条件を維持し、配置変更で利用権限を広げない。

### FR3 入力済みの割り当て変更をメニューへ移動

出典: [追加依頼:0c5c4e64]、[調査]。

- Given 管理者が未確定かつ編集可能な月で入力済みの割り当てを見ている、When 3点メニューを開く、Then 「割り当てを変える」を表示し、画面上の独立した変更ボタンは表示しない。
- Given 上記項目が表示されている、When 選ぶ、Then メニューを閉じ、既存の割り当て編集を開始する。
- Given 一般メンバー・確定済み・編集可能範囲外など従来変更できない状態、When 画面やメニューを開く、Then 変更操作を許可しない。既存の保存・取消・エラー処理を維持する。

### FR4 未入力時の入口を維持

出典: [Q1]。

- Given 割り当てが未入力で従来入力可能な状態、When カレンダーを開く、Then 「割り当てを入力する」を従来どおり画面上に表示し、3点メニューへは移さない。
- Given 同じ状態、When 入力ボタンを押す、Then 既存の入力画面を開く。
- Given 従来入力できない状態、When カレンダーを開く、Then 入力可否の条件を維持する。

## Non-Functional Requirements

### NFR1 操作性とアクセシビリティ

出典: [desc] の画面整理、操作入口を維持するための品質基準。

- 3点ボタンに読み上げ可能な名前と開閉状態を付け、キーボードで開閉・項目選択・Escapeによる終了ができる。
- メニュー終了時は適切な操作元にフォーカスを戻す（画面遷移時は遷移先の既存挙動に従う）。
- 幅320pxの画面と長い家族名でも3点ボタンが画面外へはみ出さず操作できる。

### NFR2 既存処理と品質の維持

出典: [調査]、[memory]。

- API、保存データ、認証・権限判定、月編集条件は変更しない。既存の画面遷移・編集処理を再利用する。
- 実装前にGiven/When/Thenのシナリオを用意し、各要件に対応するテストと既存テストを成功させる。行カバレッジ80%以上を維持し、既存のlint・型検査・ビルドを通す。

## Constraints

- 対象は主に CalendarPage と関連スタイル・表示文言・フロントエンドテスト。APIやインフラの変更は含めない。
- 既存のReact/TypeScriptと既存UIの見た目を使用する。

## Assumptions & Open Questions

None.

## Out of Scope

- 未入力時の「割り当てを入力する」のメニュー移動。
- 設定画面や割り当て編集の内容、権限、編集可能期間の変更。
- 他の操作ボタンの整理、無関係なリファクタリング、新規依存の導入。
