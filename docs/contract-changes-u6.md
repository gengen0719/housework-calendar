# U6 で足した契約の一覧

U6（`u6-recording`）のコード生成で、契約（`inception/contract-design/contract-summary.md`）に足したもの、形を変えたものです。項目・操作・理由の印を足すのは契約の決まりで自由です。ただし、C8 の `recordDuty` と `listTodayRecordableDuties` は**形を変えました**（下の「形（変更）」）。これらを呼ぶのは U6 だけなので、ほかの単位には影響しません。`contract-summary.md` への反映を待つ一覧として、`docs/contract-changes-u1.md`〜`docs/contract-changes-u5.md` に続けて残します。

## 形（変更）— U6 だけが呼ぶ

| 契約                           | 変えたもの | 中身                                                                                                                                                                                                                                                                            |
| ------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C8 `listTodayRecordableDuties` | 結果の形   | 契約の `Duty[] \| NO_RECORDABLE_DUTY` を、`MONTH_CONFIRMED`（理由の印）か、成功の形 `{ selectable, notSelectable }` のどちらかに置き換えた。`selectable` が 0 件の成功で「記録できる担当がない」を表し、「今日記録できる担当はありません」の文は呼び出し側（LINE の返事）が選ぶ |
| C8 `recordDuty`                | 引数・結果 | 契約の引数 `at` を `options.now` に置き換えた。成功の結果を `Duty` から `{ duty, alreadyRecorded }` に変えた                                                                                                                                                                    |

## C1 画面用 API

| 操作                              | 足したもの・変えたもの | 中身                                                                                                                                                                                                                           |
| --------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /v1/duties/{dutyId}/record` | 操作（新規）           | 子供。本文 `{ "version": integer }`（0 以上の整数）。200 `Duty`（更新後の担当。すでに自分が記録していても 200）。下の失敗の表を参照。ほかの家族の `dutyId` は、本文が誤っていても 404（本文は担当を探したあとで読む。NFR4.60） |

`POST /v1/duties/{dutyId}/record` の失敗:

| 状態 | 理由の印                | 中身                                                               |
| ---- | ----------------------- | ------------------------------------------------------------------ |
| 401  | （なし）                | セッションがない                                                   |
| 403  | `NOT_FRIEND`            | 公式アカウントをブロックしている・友だちでない                     |
| 403  | `NOT_OWN_DUTY`          | ほかの子供の担当、または管理者の要求                               |
| 404  | `NOT_FOUND`             | 担当がない・ほかの家族・`dutyId` の形が違う（DynamoDB を読まない） |
| 409  | `MONTH_CONFIRMED`       | 確定済みの月                                                       |
| 409  | `DUTY_SKIPPED_BY_ADMIN` | 「×」の担当                                                        |
| 409  | `DUTY_CHANGED`          | `version` が今の担当と違う（見せたあとに変わった）                 |
| 409  | `DUTY_ALREADY_DONE`     | すでに「済」で、記録した人が本人でない                             |
| 422  | `FUTURE_DUTY`           | 明日以降の日付の担当                                               |
| 422  | `INVALID_REQUEST`       | 本文なし・`version` が数でない・負の数・余分な項目                 |
| 500  | `INTERNAL`              | 取引の読み直しが 2 回続けて断られた、または予期しない例外          |

## C3 postback（LINE）

| data の形                                  | 足したもの   | 中身                                                                                                                                   |
| ------------------------------------------ | ------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `action=record.list`                       | 操作（新規） | リッチメニュー「やった」。1 対 1（`source.type` が user）の postback だけを記録の操作として受け付ける（NFR4.55）                       |
| `action=record.do&dutyId=<ID>&v=<version>` | 操作（新規） | 選択肢（carousel のバブル）のボタン。`dutyId` は小文字の UUID、`v` は 0 以上 9 桁以内の整数（先頭 0・小数・符号・指数は不可。NFR4.54） |

## C6 会員の窓口

| 窓口                                          | 足したもの   | 中身                                                                                                                                                                                                     |
| --------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `authorizeChild(lineUserId)`（1 対 1 の入口） | 窓口（新規） | `source.userId` から、友だちで家族に入っている利用者の `ctx` を作る。子供・管理者・家族外（記録なし・ブロック中・`lineUserId` なし）を区別して返す。グループの入口 `groupCommandGate` と同じ決まりで作る |

## C8 カレンダーの窓口

| 窓口                                        | 足したもの     | 中身                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `recordDuty(ctx, dutyId, version, options)` | 窓口（新規）   | `version`（整数または関数）と `options`（`todayOnly`、`now`、`route`）を取る。結果は `{ duty, alreadyRecorded }` / `NOT_FOUND` / `NOT_OWN_DUTY` / `MONTH_CONFIRMED` / `DUTY_SKIPPED_BY_ADMIN` / `FUTURE_DUTY` / `NOT_TODAY_DUTY` / `DUTY_CHANGED` / `DUTY_ALREADY_DONE` / `INTERNAL`。取引は担当の `UpdateItem` ＋ 月の状態の ConditionCheck ＋ 種類の単価の ConditionCheck の 3 項目。断られたら 1 回だけ読み直してやり直す |
| `listTodayRecordableDuties(ctx, today)`     | 窓口（新規）   | 今日の記録できる担当を `{ selectable, notSelectable }`（または `MONTH_CONFIRMED`）で返す。読み取りは月の Query 1 回で、担当の数で増えない（NFR1.21）                                                                                                                                                                                                                                                                         |
| `onDutyRecorded(hook)`                      | 仕組み（新規） | 担当が「済」になったときに 1 回だけ呼ばれる（`alreadyRecorded` のときは呼ばない）。書けたあとに呼び、関数が投げても記録の結果は変えない（`DUTY_RECORDED_HOOK_FAILED` の警告を残す）。U8 が申し出の取り下げに使う                                                                                                                                                                                                             |

## C10 理由の印と文言

| 印または文言                                | 文言                                                             |
| ------------------------------------------- | ---------------------------------------------------------------- |
| `DUTY_CHANGED`（新しい印。LINE の中だけ）   | この担当は先に変更されました                                     |
| `DUTY_ALREADY_DONE`（新しい印）             | この担当はすでに『済』になっています                             |
| `NOT_TODAY_DUTY`（新しい印。LINE の中だけ） | （LINE の返事は「この担当は先に変更されました」を使う）          |
| `ADMIN_RECORD_GUIDE`（新しい文言）          | お手伝いの記録は子供のメニューです。記録の修正は画面からできます |
| `JOIN_FAMILY_FIRST`（新しい文言）           | 先に家族に参加してください                                       |
| 記録の選択肢の見出し                        | どのお手伝いを記録しますか                                       |
| 記録の成功（値を入れる）                    | {お手伝い}を記録しました（{時:分}）                              |
| 画面の確認（値を入れる）                    | {月}/{日} {お手伝い}を記録しますか                               |
| 画面の確認のボタン                          | 記録する                                                         |
| 記録の失敗（`INTERNAL`）                    | うまく記録できませんでした。もう一度お試しください               |

既存の印と文言 `MONTH_CONFIRMED`・`NO_RECORDABLE_DUTY`・`FUTURE_DUTY`・`DUTY_SKIPPED_BY_ADMIN`・`NOT_OWN_DUTY` は、そのまま使う。

## データとログ（決めごと）

- DynamoDB: U6 はテーブルを足さない（`Calendar` は U5、`ChoreTypes` は U4 で作済み）。担当の項目に書き写す値は `status=done`・`recordedAt`・`recordedBy`・`unitPrice`・`version+1`
- 環境変数: `line` に `CALENDAR_TABLE` と `CHORE_TYPES_TABLE` を足した（`api` の環境変数は変えない）
- `line` のロール: `Calendar` に `GetItem`・`Query`・`UpdateItem`・`ConditionCheckItem`（`PutItem`・`DeleteItem`・`Scan` はない）。`ChoreTypes` に `GetItem`・`Query`・`ConditionCheckItem`（読むだけ）。`api` のロールは U6 で変えない
- ログ: `DUTY_RECORDED`（記録が成功した）、`DUTY_RECORDED_HOOK_FAILED`（フックが投げた。警告）。名前や中身は出さない

## U7〜U9 への引き継ぎ

- **U7（状態の変更・月の確定）:** 「済」を取り消すとき、記録の項目（`recordedAt`・`recordedBy`・`unitPrice`）を消すかは U7 が決める。担当を書き換えるときの条件（`dutyId` と `version`、月の確定の確かめ）は U6 と同じにする
- **U8（代わりにやる）:** `onDutyRecorded` で、「済」になった担当の申し出を取り下げる。U6 は登録の口だけを用意し、今は何も登録しない
- **U9（お小遣い）:** 「済」の担当の `unitPrice` を種類ごとに足して額を出す。`recordedAt` の日付ではなく、担当の `date` の月で数える

## 要件への反映を待つもの

- **記録の要件**（要件の番号は、反映のときに合わせる）: `POST /v1/duties/{dutyId}/record` の本文と応答、リッチメニューと選択肢の postback の形、記録の取引の条件（`version` と月の確定、単価の確かめ）、1 対 1 の入口の決まり（子供・管理者・家族外の区別）を、要件の書き方に合わせて足す
